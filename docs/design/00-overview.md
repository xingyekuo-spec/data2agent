# 00 · 产品总览

> 状态:草案 v0.1(2026-07-10)· 本文收拢散落在 README / 代码注释 / 模板 caveats 里的全部产品决策,是其余设计文档的入口。

## 1. 一句话定位

**Data to Agent, for factories** —— 把中小制造企业锁在无 API 老系统里的数据,安全地接给任何 AI Agent。

## 2. 问题与用户

中小制造企业(50–500 人)的经营数据分散在鼎捷 / 金蝶 / 用友 ERP、MES、SRM、CAD 和大量 Excel 里。这些系统普遍没有可用的 API,厂商接口贵且慢;而 Agent 时代的全部价值前提是"数据可达"。

| 用户 | 诉求 | 对应交付 |
| --- | --- | --- |
| 工厂老板 / 厂长 | 30 秒看到 Agent 用自家数据干活(接单评审卡) | 展厅演示链(docs 04) |
| 工厂 IT / 实施伙伴 | 敢把它装进内网:只读、白名单、可审计 | 抽取框架(docs 02) |
| Agent 开发者 | 五分钟拿到干净的业务对象和指标口径 | MCP 网关(docs 03) |
| 连接器贡献者 | 清晰的模板契约,贡献金蝶 / 用友 binding | 元模型(docs 01) |

## 3. 总体架构

```
源系统(鼎捷 E10 / 易飞 / 金蝶 / 用友 / Excel …)
   │  只读适配器:白名单 / 错峰限时 / 限流 / 全量 SQL 审计     → docs 02
   ▼
原样落地层 raw_*:水位增量 + 回看 + 分段对账 + 隔离区          → docs 02
   ▼
声明式映射:元模型 binding(单一事实来源)                     → docs 01
   ▼
业务对象层(Customer / SalesOrder / …)+ 指标口径(MetricDef)
   ▼
MCP 网关:query_objects / query_metrics,看/说/做 治理档位     → docs 03
   ▼
任何支持 MCP 的 Agent(接单评审演示链 → docs 04)
```

上图是**逻辑架构**。现场**物理部署**(薄中间服务器 + 内网数据平台、内网流式 agent 出站推送)见 docs 02 §12。

核心设计原则(全部已在代码中兑现或将兑现,违反即 bug):

1. **契约先行**:元模型是唯一事实来源;映射引擎、MCP 参数校验、对账工具、白名单推导全部消费它,不允许旁路。
2. **诚实声明**:binding 分 `draft/verified`,指标分 `certified/draft/deprecated`;未经现场校准的口径,警示必须贯穿到 Agent 收到的每个响应里。
3. **安全可审计**:碰客户数据库的每一行代码都在本仓库、可审计;只读、白名单、限时、限流是代码强制,不是文档承诺。
4. **按需拉动**:对象模板、指标实现、演示能力都由真实场景拉动,不为完整性提前建设。

## 4. 产品范围(诚实声明)

data2agent 是一个**完整可用的产品**:把制造业 ERP 数据安全接给 AI Agent 的全链路 ——
抽取框架、国产 ERP 连接器、元模型与模板、MCP 网关(看/说/做 治理)、运维控制台、
数字厂长展厅,全部在本仓库、可运行、可审计。

做不做的判断标准是**按需拉动**:能力由真实场景驱动,不为完整性提前建设。
当前版本已覆盖"数据安全到达 Agent + 接单评审";以下为路线上的后续能力
(尚未实现,诚实标注、不夸大):口径校准(draft→certified)、数据对账、
主数据对齐、"做"档审批治理、行业知识包。

## 5. MVP 与验收(渔具客户,鼎捷 E10)

首个验证工厂为渔具外销厂,ERP 为鼎捷 E10,核心场景是**接单评审**(询单 → 历史成交 / 毛利 / 交期 → 建议卡)。

验收标准:

1. E10 只读抽取在客户内网稳定运行:错峰窗口内完成日增量,连续一周无事故;
2. 首批 5 个对象(Customer / Material / Quotation / SalesOrder / SalesOrderLine)binding 经现场数据字典核对,全部置为 `verified`;
3. `quote_response_hours` 于启动周完成基线实测(MVP 验收指标);
4. 接单评审卡通过老板测试:非技术人 30 秒看懂 Agent 干了什么。
