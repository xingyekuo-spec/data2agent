## 1. 目标

在不开始 Vue 页面、不扩展后端业务功能的前提下，为现有控制台 API 建立可生成、可审查、可回归的契约基线，使后续前端不再依赖手写类型或猜测响应结构。

本里程碑完成后应满足：

- 每个现有 `/api/**` 端点都声明明确的 Pydantic 请求和响应模型；
- OpenAPI 快照可由后端代码确定性生成；
- 接口变化未同步快照时 CI 失败；
- 当前 Jinja2、`/v0` 和已有测试依赖的 wire shape 保持兼容；
- 错误、列表边界、时间语义和动作响应不再隐含于实现代码中。

## 2. 范围

### 2.1 本里程碑包含

- 盘点并锁定当前管理 API 路由、方法、请求和响应结构；
- 将散落在 `data2agent/console/app.py` 的契约模型提取到独立模块；
- 为全部现有端点增加 `response_model` 和已知错误响应描述；
- 为列表端点记录过滤条件、默认数量和强制上限；
- 明确现有 SQLite 文本时间字段的语义，不伪装为已完成时区迁移；
- 生成并提交 `console-ui/openapi.json`；
- 增加 OpenAPI 快照漂移检查和契约测试；
- 更新受模型校验影响的现有测试，但不改变业务含义。

### 2.2 明确不包含

- 创建 Vue/Vite 工程或生成 TypeScript 类型；这些属于 M2；
- 新增总览管道、统一 Run 详情、对象数据浏览等 v0.2 新业务端点；
- 把现有列表响应强制改成分页 envelope；
- 迁移或重写 SQLite 中已有的无时区时间值；
- 修改 mapping、binding 或指标；
- 开放新写操作、ERP 写回、多租户、PostgreSQL 改造；
- 将 `/ingest/reconcile` 并入 `/api/**`。

## 3. 当前代码事实

当前 API 集中在 `data2agent/console/app.py`。请求体已有少量 Pydantic 模型，但响应主要标注为 `dict` 或 `list[dict]`，OpenAPI 无法为前端提供稳定字段类型。

### 3.1 当前端点清单

| 方法与路径 | 当前成功响应 | M1 处理方式 |
| --- | --- | --- |
| `GET /api/setup/status` | setup 状态、配置路径、home | 建立具名响应模型 |
| `POST /api/setup` | 成功信息或字段错误列表 | 建立成功/校验失败模型并声明错误响应 |
| `GET /api/overview` | landing、模式、source/object 汇总 | 建立嵌套响应模型，保留当前对象结构 |
| `GET /api/runs` | 运行记录数组 | 使用 `list[RunSummary]`，M1 不增加 envelope |
| `GET /api/quarantine` | 隔离记录数组 | 使用 `list[QuarantineRecord]`，保留筛选与上限 |
| `GET /api/audit` | SQL 审计数组 | 使用 `list[AuditRecord]`，保留当前 wire shape |
| `GET /api/config` | setup 状态、templates、landing | 建立只读配置响应模型 |
| `POST /api/config` | 保存结果、错误和重启要求 | 建立配置操作响应模型 |
| `POST /api/config/validate` | 校验结果和字段错误 | 与保存动作共享明确模型 |
| `GET /api/services` | ingest/MCP/apply/console 探测结果 | 建立服务名到探测结果的具名结构 |
| `GET /api/logs` | 是否成功、日志文本 | 建立响应模型，不把失败改为空文本 |
| `GET /api/debug/raw-table` | table、offset、limit、total、rows | 保留现有分页 envelope，约束动态行值类型 |
| `POST /api/debug/mcp-call` | QueryService 的工具结果 | 用白名单工具的联合响应或受控 JSON 值描述 |
| `POST /api/actions/sync` | executed、note | 建立动作接受/拒绝响应模型 |
| `POST /api/actions/reconcile` | executed、note | 复用动作响应模型 |
| `POST /api/actions/apply` | executed、results、aborted | 建立 apply 结果模型 |
| `POST /api/actions/retry` | executed 与单次 apply 结果 | 建立 retry 结果模型 |

非 API 页面 `GET /`、`GET /config`、`GET /logs`、`GET /debug` 和 `GET /v0` 不进入 JSON 响应模型改造，但必须保留回归测试。

### 3.2 已知兼容约束

- `runs`、`quarantine` 和 `audit` 当前直接返回数组；现有测试和潜在页面调用依赖这一结构。
- `overview` 和 `config` 当前直接返回对象，不带统一的 `data` 外壳。
- FastAPI 现有 HTTP 错误响应采用 `{ "detail": "..." }`。
- SQLite 的 `started_at`、`finished_at`、`created_at`、`ts` 等字段当前是文本，部分值由无时区的本地 `datetime.now()` 产生。
- MCP debug 返回值随白名单工具而异，不能用无边界的 `dict[str, Any]` 让核心响应重新退化为 `unknown`。

## 4. 本里程碑的契约决策

### 4.1 兼容优先

M1 只给当前 wire shape 增加类型，不改变成功响应最外层结构。需要统一分页 envelope 的新接口在对应功能里程碑中以兼容方案引入，不能借“模型化”直接破坏现有消费者。

允许的兼容改动：

- 增加可选字段；
- 收紧实现本来就保证的字段类型；
- 补充 OpenAPI 描述、示例、边界和错误响应；
- 修复实际返回值与已声明模型不一致的问题，但保持业务含义。

需要单独评审的非兼容改动：

- 数组变对象或新增统一 `data` 外壳；
- 字段重命名、删除或改变空值语义；
- 状态枚举收紧后拒绝历史数据库中已存在的值；
- 将成功 HTTP 状态改为错误状态或反向修改。

### 4.2 错误模型以真实行为为基线

建立以下最小模型：

```text
HttpError
└─ detail: string

FieldError
├─ field: string
└─ message: string

ValidationResult
├─ ok: boolean
├─ errors: FieldError[]
└─ restart_required?: boolean
```

已知的 `401`、`409`、`422` 和适用的 `500` 在路由 OpenAPI `responses` 中显式声明。全局 `error_id`、异常追踪和统一错误码属于后续可观察性工作；M1 不声明尚未实现的字段。

### 4.3 时间字段不伪造时区正确性

M1 将历史落库时间保持为 `str | None`，在字段描述中标记为“legacy local ISO text，当前不保证 offset”。本里程碑新增的契约生成时间必须使用带 `Z` 或 UTC offset 的 ISO 8601。

把所有历史字段改为带时区 `datetime` 需要先确定原始时区和迁移策略，另列后续任务。在完成迁移前，OpenAPI 不得错误宣称这些字段都是 `date-time` 且带时区。

### 4.4 JSON 值必须有边界

动态 raw 行和 MCP 原始结果使用递归 `JsonValue` 类型表达，而不是 `Any`。白名单 MCP 工具若返回结构已经稳定，应优先建立工具级响应模型；确实动态的节点才使用 `JsonObject`。

### 4.5 OpenAPI 是生成物

`console-ui/openapi.json` 由脚本生成，禁止手工修改。快照采用固定排序、UTF-8、2 空格缩进和文件末尾换行，避免环境差异造成无意义漂移。

## 7. 测试矩阵

| 场景 | 必须验证的契约结果 |
| --- | --- |
| 已配置且有数据 | 响应通过具名模型，字段类型稳定 |
| 已配置但无数据 | 正常空数组或零计数，不带错误语义 |
| setup mode | 允许的 setup 端点正常；其他管理端点返回明确 `409` |
| Token 缺失或无效 | 返回 `401` 错误模型，不返回空业务数据 |
| limit/offset 越界 | 返回参数错误或被明确限幅，不执行无限查询 |
| 服务不可达 | 服务探测结果表达失败，不伪装为健康 |
| MCP 未知工具 | 被白名单拒绝，响应符合错误契约 |
| apply/retry 业务拒绝 | 与 HTTP 异常、执行成功可区分 |
| legacy 时间值 | 不因无 offset 被错误丢弃，也不宣称已标准化 |
| OpenAPI 未更新 | `--check` 非零退出并给出修复命令 |

## 9. M1 交给 M2 的稳定输入

M1 完成后，M2 只接收以下输入：

- `console-ui/openapi.json`；
- 快照生成与检查命令；
- API 认证、错误和动态 JSON 的契约说明；
- 当前 API 与后续 v0.2 新端点的缺口列表；
- 明确保留的 Jinja2/`v0` 兼容边界。

M2 再创建 Vue 工程、运行 `openapi-typescript` 并建立 fixture。若 M2 发现契约缺失，应先回到后端模型和 OpenAPI 快照修正，不在 TypeScript 侧用 `any`、强制断言或手写重复类型掩盖问题。
