## 1. 目标

将运行列表、数据集、Preview、字段血缘和 MCP evidence 的既有验证事实，收敛为一份可重复运行、可在 Console 查看、可下载 JSON 的只读验收报告。

Validation Run 回答的是：**在某个确定时刻，这个部署是否满足 v0.3 验收条件；若不满足，具体哪一项、哪个对象、哪个版本或哪条证据导致失败。**

一次运行固定输出：

```text
validation run_id
+ started_at / finished_at / overall_status
+ deployment snapshot（非敏感配置摘要）
+ published dataset/template/binding snapshot
+ check[]（pass | warning | fail | skipped）
+ evidence links（run / dataset / object / lineage / gateway evidence）
+ bounded, redact-safe JSON report
```

M6 不执行 sync、apply、publish、rollback、隔离重试、mapping 保存或 ERP 写回；它只读取现有事实来源，并将自己的 report/run 元数据短事务持久化。

## 2. 范围与边界

### 2.1 可复用事实来源

- M1/M2：dataset/object version、published snapshot、publish/rollback 与运行记录；
- M3：mapping preview、枚举 gap、derived 覆盖率与隔离摘要；
- M4：字段 lineage、run/object/raw 输入链接及脱敏读取；
- M5：principal/session/query/proposal evidence、摘要、detail API 与持久 audit；
- `d2a_sync_run` / `d2a_run_step`：已包含 `validation` run type；
- Console：OpenAPI、Mock/Real、运行列表和 `/v1` 路由基础设施。

### 2.2 非目标

- 不增加 v0.4 的 TLS、多主体凭据轮换、RBAC、batch receipt、schema fingerprint 或压测；
- 不导出 raw、敏感原值、Token、完整 SQL、环境变量、绝对路径或 traceback；
- 不创建第二套 pipeline、dataset、lineage 或 evidence 事实来源；
- 不生成 HTML/PDF；M6 只提供页面与 JSON。

## 3. 冻结契约

### 3.1 状态和 overall

每个 check 只可为 `pass | warning | fail | skipped`：

| 状态 | 含义 | overall 影响 |
| --- | --- | --- |
| `pass` | 已完成且满足条件 | 无 |
| `warning` | 已完成但存在草稿/时效等可见风险 | overall 至少为 warning |
| `fail` | 条件不满足或无法安全完成检查 | overall 为 fail |
| `skipped` | 模式或先决条件明确不适用 | 不计为 pass；由 check 声明是否阻断 |

`overall_status` 固定为 `pass | warning | fail`：任一阻断 fail 即 fail；无 fail 但有 warning 或非阻断 skipped 即 warning；所有必需 check pass 才是 pass。

每项保存 `check_id/title/status/blocking/summary/started_at/finished_at/detail/evidence[]`。`detail` 是有界结构化 JSON；错误只保存稳定 reason code 与安全说明。

### 3.2 固定检查目录

| check_id | 检查内容 | 主要事实来源 | 失败规则 |
| --- | --- | --- | --- |
| `service_reachable` | Console、配置、SQLite 可读 | app state / landing | 不可读 fail |
| `source_connectivity` | 已配置 ERP/source 只读连接状态 | config / health | 未配置 skipped；失败 fail |
| `readonly_whitelist` | read-only adapter、whitelist、出口脱敏策略 | config / adapter | 不满足 fail |
| `sync_execution` | 最近 sync/ingest 状态与时效 | run/step | 缺失/失败 fail；过期 warning |
| `landing_and_push` | landing/push 结果与批次摘要 | run/landing metadata | 失败 fail；未启用 skipped |
| `raw_presence` | 必需 raw 表或受控样本存在 | whitelist / landing | 缺失 fail |
| `published_dataset` | published dataset、关键对象、object version 一致 | published snapshot | 缺失/不完整 fail |
| `quarantine_breaker` | 隔离率、breaker、serving state | quarantine/run | breaker fail；阈值 warning |
| `mapping_preview` | draft binding、枚举 gap、derived 覆盖率 | templates/M3 facts | draft warning；不得伪造 verified |
| `mcp_query` | 对 published 数据集的最小只读 MCP 查询 | QueryService/M5 | 无可核验 query fail |
| `masking` | MCP/object/lineage 出口敏感字段仍脱敏 | template flags + probe | 明文泄漏 fail |
| `evidence_integrity` | query/proposal 的版本、摘要、会话事实可读 | M5 tables | 损坏 fail；无 proposal warning |
| `cross_surface_consistency` | config/template/dataset/object/version 一致 | snapshots/API | 不一致 fail |

检查只能读取指定的既有事实；任何实时 probe 必须复用既有只读 adapter/QueryService，设置超时、行数和返回大小上限。

### 3.3 存储与原子性

复用 `d2a_sync_run(run_type='validation')` 作为 Run 身份，新增：

```text
d2a_validation_report
  run_id PK / report_schema_version / source / overall_status
  started_at / finished_at / deployment_json
  dataset_version / template_version / summary_json / report_json

d2a_validation_check
  run_id + ordinal PK / check_id / title / status / blocking
  started_at / finished_at / summary / detail_json / evidence_json
```

- report/check 与 validation run 在同一短事务提交；写失败不返回“完成”报告；
- 表有 migration、索引与 freeze trigger，禁止 UPDATE/DELETE；
- report JSON 由 check 行规范化生成；页面与下载读取同一事实；
- run 开始冻结 published dataset/template snapshot，禁止末尾重新读取 current 指针；
- 只保存非敏感配置摘要、版本、计数、reason code 与相对 API 链接；
- 检查失败必须记 fail/warning，禁止吞错标 pass。

### 3.4 API 与下载

```text
POST /api/validation/run
GET  /api/validation/runs/{run_id}
GET  /api/validation/runs/{run_id}/report.json
```

`POST` 不接受任意 SQL、source/table/path、principal、session 或“忽略失败”参数；最多接受空 body 或 `include_mcp_probe`（默认 true）。已有 validation 运行中时返回 `409 validation_in_progress`。

- 404：不存在的 validation run；
- 409：并发 validation 或尚未完成；
- 422：非法参数；
- 500：`validation_unavailable`，不泄露内部异常；
- JSON 下载为 UTF-8 `application/json`，建议文件名 `data2agent-validation-<run_id>.json`。

### 3.5 Vue 页面

新增 `/v1/validation`：展示最近运行的 overall、时间、source、dataset version 与固定顺序 checks；支持开始只读验收、运行中状态、证据跳转和 JSON 下载。

Mock 必须覆盖 `running/pass/warning/fail/skipped/empty/unknown error`；Real 不伪造结果。页面不展示 raw、Token、SQL 或堆栈，并支持窄屏与键盘操作。

## 5. 测试矩阵

### 5.1 模型、存储与 API

- check ID 顺序、状态优先级、overall 聚合与 schema 兼容；
- report/check 不可更新或删除，故障 rollback 无半 report；
- 并发两个 POST 只有一个运行，另一个稳定 409；
- detail 与下载 JSON 结构一致，不含 Token、raw、SQL、绝对路径或 traceback；
- 旧库迁移、重复初始化、只读 reopen、SQLite busy 有界失败。

### 5.2 检查内核与一致性

- 13 类 check 各覆盖 pass/warning/fail/skipped 至少一个场景；
- 缺 published、构建失败、breaker、raw 缺失、draft mapping、MCP 不可用、损坏 evidence、版本不一致；
- 敏感字段 probe 验证 `***` 仅在安全响应中出现；
- 运行前后比对 raw、对象表、dataset pointer、quarantine、水位、proposal/evidence：除 validation report/run/audit 外均不变；
- publish/rollback 并发下报告只引用完整旧版本或完整新版本，不混版。

### 5.3 前端、E2E 与发布

- POST/detail/download 的认证、200/404/409/422/500、OpenAPI 和 TypeScript；
- running/pass/warning/fail/skipped、下载、evidence 跳转、刷新和窄屏；
- E2E：seed → sync → apply/publish → validation → JSON 下载 → MCP proposal evidence；
- `/`、`/v0`、`/v1`、M3 preview、M4 lineage、M5 MCP Lab 与便携包不回归。

## 7. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 验收流程变成写操作编排器 | registry 只允许读取既有事实；测试前后比对业务表与指针 |
| 报告混用版本 | run 开始冻结 snapshot；check 只消费该上下文 |
| skipped 掩盖缺陷 | 区分可选 skipped 与必需 fail；overall 明确聚合 |
| JSON 泄漏敏感数据 | 白名单 schema、长度上限、敏感扫描与 response tests |
| 前端另造事实来源 | 只消费 validation detail/download API，不在浏览器重算 gate |
| 误扩大到 v0.4 承诺 | release 文案明确 v0.3 可验证边界 |
