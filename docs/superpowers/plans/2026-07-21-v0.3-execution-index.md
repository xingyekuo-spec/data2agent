## 1. 版本目标

v0.2 回答“发生了什么”，v0.3 回答“为什么得到这个结果”。发布门槛是任意关键结果可以追溯到输入、映射规则、已发布数据集版本和查询时的结果摘要。

## 2. 执行规则

1. 严格按 `M1 → M2 → M3 → M4 → M5 → M6` 推进；未通过当前里程碑退出门禁，不切换下一里程碑。
2. 版本、preview、血缘和 evidence 必须消费同一元模型，不建立旁路规则副本。
3. preview 不写正式对象表、隔离区、水位或当前数据集版本。
4. MCP 只能读取 `published` 数据集；构建失败或熔断必须继续服务上一稳定版本。
5. 血缘和 evidence 的敏感值遵循现有出口脱敏规则，不能成为解敏旁路。
6. 每项任务按“契约/设计 → 实现 → 自动测试 → 页面验收 → 证据归档”闭环。
7. v0.4 的批次回执、E6b、生产 TLS、多主体凭据轮换和试点压测不提前进入本队列。

## 4. 依赖关系

```text
M1 版本身份/元数据
  └─ M2 原子发布与 dataset_version
       ├─ M3 preview（复用正式转换核心）
       ├─ M4 lineage（绑定已发布 dataset_version）
       └─ M5 evidence（记录查询实际 dataset_version）
            └─ M6 一键验收与发布
```

M3 与 M4 都依赖 M2 的稳定版本语义；M5 依赖 M2 提供查询实际读取的数据集版本。为保持单一主线，不并行打开多个里程碑。

## 5. v0.3 发布总门禁

- 关键对象字段具备字段级血缘；
- 映射 preview 与正式 apply 隔离；
- 对象层原子发布并记录 dataset/object version；
- MCP evidence 按主体和会话隔离；
- 一键验收覆盖完整演示链；
- 接单评审建议卡中的关键数字能够追溯到查询结果摘要；
- `/`、`/v0`、`/v1`、现有 CLI 和便携包能力无回归；
- 后端、前端、OpenAPI、分发和端到端测试全部通过。
