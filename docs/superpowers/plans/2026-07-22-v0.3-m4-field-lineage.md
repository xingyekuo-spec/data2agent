## 1. 目标

在正式数据集 apply 时，为每一条成功物化的对象记录生成可复现的字段级血缘，并把它绑定到不可变的：

```text
dataset_version / object_version / template_version / binding_hash / map_batch_id
```

用户在对象数据页选择一条记录后，可以在三次点击内看到任一字段的：

- 对象业务键、属性名和最终值；
- 实际读取的 source、raw 表、raw 列、源记录主键和抽取批次；
- join 的锚表外键、目标表主键和目标值；
- map、类型转换、derived 的有序执行步骤及 before/after；
- derived 命中的规则下标、条件、default 或未命中原因；
- 映射批次、binding 状态、模板版本和当前已发布数据集版本；
- 无法追溯时稳定、明确的 reason code。

血缘证明“系统在该次正式 apply 中实际读取并转换了什么”，不替代现场数据字典核对，也不把 M3 Preview 的运行时试算结果误当作正式证据。

## 2. 开始基线与现有缺口

### 2.1 可复用能力

- M1 已提供确定性 `template_version`、`binding_hash` 和不可变 dataset/object version 元数据；
- M2 已提供 `objv_*` 候选表、完整数据集构建、原子发布、上一稳定版本、回滚和保留策略；
- M3 已把正式 apply 与 Preview 统一到 `mapping_transform.evaluate_object_rows()`，并返回结构化 issue 与 derived 命中；
- `build_select()` 已解析 field/map/join 表达式，并且正式 apply 只读取落地 raw 表；
- published snapshot 已冻结 `TemplatePack`，查询时能得到实际 `dataset_version/object_version/template_version/binding_hash`；
- 对象浏览已有按 frozen template 输出列、服务端截断/脱敏和访问审计的基础能力。

### 2.2 必须消除的缺口

- `RowEvaluation` 还没有逐字段 read/map/coerce/derived trace，apply 目前只保留最终 good/quarantine；
- 正式 SELECT 没有稳定投影锚表/关联表主键、join 外键和各 raw 行 `_d2a_batch_id`；
- `apply_object()` 不接收 `dataset_version/object_version`，`map_batch_id` 也在函数内部临时生成；
- 候选表写入会自行 `commit`，还不能和血缘写入组成同一对象构建事务；
- landing schema 没有字段节点、输入边、血缘版本或完整性计数；
- 发布校验、失败恢复、回滚和 GC 尚不知道血缘工件；
- 既有 API 路径中的单个 `{key}` 不能直接无歧义表达 `SalesOrderLine` 的复合业务键；
- 控制台没有 lineage contract、Mock、状态 store 或字段追溯抽屉；
- 升级前创建的 published 数据集没有血缘，接口必须明确说明而不能伪造或笼统 404。

## 3. 冻结契约

### 3.1 唯一事实来源与可见性

字段血缘只由正式 `build_dataset → apply_object` 路径生成。可见性固定为：

```text
raw 快照读取
  → mapping_transform 单一转换评估
  → 熔断判断
  → 候选 objv_* + lineage 同一对象事务写入
  → 全对象完整性校验
  → dataset 原子 publish
  → lineage API 只解析当前 published snapshot
```

约束：

1. Preview 继续只产生内存 trace，不写正式 lineage、dataset/object version、候选表或隔离区；
2. lineage API 不读取当前模板去解释历史数据，只使用 published dataset 冻结的 `template_snapshot`；
3. API 不回退遗留 `obj_*`，不把 building/failed/retired 非当前数据集伪装成当前血缘；
4. 对象字段、对象记录和 lineage 必须属于同一个 `dataset_version + object_version`；
5. M4 不实现第二套 map/derived/coerce 逻辑，trace 必须在 M3 的实际求值步骤中产生。

### 3.2 持久化模型

采用“字段节点 + 输入边”两层模型，避免把 derived 多条件、join 两端和字段最终结果挤进单行 JSON。

`d2a_field_lineage`：每个成功物化对象记录的每个模板属性一行。

```text
dataset_version / object_version / object / object_key_json / object_key_hash
property / result_value_json
trace_status(available|unavailable) / unavailable_reason
transform_kind(direct|derived|unmapped) / transform_steps_json
source / map_batch_id / binding_hash / binding_status / template_version
```

`d2a_field_lineage_input`：字段的零到多条输入边。

```text
dataset_version / object / object_key_json / property / input_ordinal
role(value|join_fk|derived_condition)
source / source_table / source_pk_json / source_column / source_value_json
extract_batch_id / join_json
```

主键与索引：

- 字段节点主键：`(dataset_version, object, object_key_json, property)`；
- 输入边主键：字段节点主键加 `input_ordinal`；
- `object_key_hash` 使用完整 SHA-256 十六进制，建立 `(dataset_version, object, object_key_hash)` 查询索引；
- 同一数据集/对象/hash/property 建唯一约束；极小概率 hash 冲突必须让构建失败，不能返回错误记录；
- 两表以 `(dataset_version, object)` 外键指向 `d2a_object_version`，删除仅能走受控保留清理；
- 写入后的字段节点和输入边不可更新，失败重试使用新的 dataset/object version。

`d2a_object_version` 增加：

```text
lineage_schema_version INTEGER NULL  # 旧版本 null；M4 新构建固定为 1
lineage_field_count INTEGER NULL     # 成功字段节点数；building 阶段写入后冻结
```

新构建必须满足：

```text
lineage_field_count == object_row_count × len(template.properties)
```

输入边数量可变，不用它判断字段完整性。未映射属性也要写字段节点，`trace_status=unavailable`、`unavailable_reason=property_unmapped`，从而区分“确实没有来源”和“工件丢失”。

迁移必须对旧库幂等：旧 object version 两列为 `NULL`，不回填伪血缘；初始化、重复初始化、只读打开和 freeze trigger 均有回归测试。

### 3.3 业务键与 `{key}`

对象键按 frozen template 的 `keys` 顺序规范化为 JSON pair 数组，例如：

```json
[["order_no","SO-001"],["line_no",10]]
```

规则：

- 保留 `null/string/number/bool` 类型，不用展示字符串做身份；
- 紧凑 UTF-8 JSON 后计算完整 SHA-256，得到 64 位 `key token`；
- lineage 存规范化 JSON 和 hash；URL 只使用 hash，避免复合键分隔、斜杠和编码歧义；
- `ObjectRowsPageResponse` 增加与 `rows` 对齐的 `lineage_refs[]`，每项包含 `row_index/key_token/object_key`；
- `object_key` 仍走 frozen template 的敏感字段显示规则，`key_token` 只作不透明定位符；
- 后端对新 lineage version 查询 hash 后还要核对唯一记录和版本，不能只信客户端提交的键内容。

公开路径保持路线图冻结形式：

```text
GET /api/objects/{object}/{key}/lineage
```

其中 `{key}` 明确定义为服务端返回的 64 位 lineage key token，而不是仅支持单键对象的原始业务键。

### 3.4 转换 trace

`mapping_transform.py` 在真实求值点扩展 `RowEvaluation.field_traces`；每个 trace 至少包含：

```text
property / raw_value / result_value / status / unavailable_reason
steps[] / derived_hit / input_roles[]
```

有序 steps 只记录实际执行过的转换：

```text
read → join(可选) → map(可选) → coerce(可选) → derived rule/default(可选)
```

语义固定为：

- direct 字段保留读取值与最终规范化值；
- map 明确记录 before/after 和是否命中声明项；
- coerce 记录目标类型及 before/after；
- derived rule 记录声明顺序下标、实际命中的条件和值；default 单独标记；
- join 字段保留锚行主键、锚外键值、目标行主键、目标列值和双方抽取批次；
- join 目标不存在时字段节点写 `join_target_missing`，仍可保留锚外键输入边；
- 属性没有 field_map/derived 时写 `property_unmapped`；
- quarantined 行不进入对象表，也不写正式 lineage；其结构化失败仍只进入现有 quarantine。

为了拿到实际源记录身份，新增共享的 `SelectPlan`：

```text
sql / params / exprs / provenance projections
```

`build_select_plan()` 成为 canonical builder；现有 `build_select()` 保留为兼容包装并返回原 tuple。正式 apply 使用 plan 的 collision-safe 内部别名投影：锚/关联表 DDL 主键、join 外键、`_d2a_batch_id` 和 derived 条件列。Preview 与 MCP 的默认 SQL 行为不变。

provenance planner 只负责“这一列来自哪条 raw 记录”，不负责重新计算字段结果；最终 trace 必须把 planner 的源引用与 `mapping_transform` 的真实 field trace 合并。

### 3.5 值证据序列化

`source_value/result_value/before/after` 使用稳定 `ValueEvidence` JSON，而不是 `repr()`：

```text
kind: scalar|null|bytes|truncated
value: JSON scalar（scalar/null）
preview / sha256 / length: bytes 或超长文本
```

规则：

- 常规 JSON 标量保留类型；日期、Decimal 沿用落地层规范化语义；
- BLOB 不复制全文，记录长度和 SHA-256；
- 超过固定上限的文本记录有界 preview、总长度和 SHA-256；
- 截断必须显式返回，不能把 preview 冒充完整源值；
- API 展示前再按 frozen template/source classification 脱敏，数据库中的证据不能绕过服务端出口。

### 3.6 apply 原子性

`dataset_publish` 在创建 object version 时生成并传入：

```text
ApplyVersionContext(dataset_version, object_version, map_batch_id,
                    template_version, binding_hash, binding_status)
```

正式 apply 顺序：

1. 用 `SelectPlan` 一次读取字段值和 provenance；
2. 调用唯一 `evaluate_object_rows()` 得到 mapped/quarantine 与 field trace；
3. 写 quarantine 并执行现有严格 `quarantined / total > threshold` 熔断；
4. 熔断时不创建候选表、不写 lineage、不标记 object built；
5. 未熔断时，在一个显式事务内创建并写入 `objv_*`、字段节点、输入边及 lineage count；
6. 任一写入或完整性检查失败，事务回滚候选表和 lineage；dataset 构建进入现有 failed 清理；
7. 全对象通过后才把 dataset 标记 ready，publish 指针事务不扫描也不重写 lineage。

`write_candidate_table()` 增加由调用方控制事务的内部能力；不得继续在候选表成功但 lineage 失败时提前 commit。

遗留 `apply_objects()` 可继续生成未发布候选表，但没有 `ApplyVersionContext` 时不写正式 lineage。只有 `build_dataset` 产出的版本可发布并通过 M4 lineage 完整性门禁。

### 3.7 发布、回滚、失败恢复与 GC

- publish：候选 `lineage_schema_version=1` 时，发布前验证物理行数、字段节点数、版本/hash/batch 一致；不在短临界事务内扫描血缘正文；
- rollback：回到 `current.previous` 时自然读取该历史版本自己的 lineage；旧版本 `lineage_schema_version=NULL` 可以回滚，但接口返回明确 unavailable；
- stale building recovery：标记失败并清理未受保护候选表时，同时删除该 dataset/object 的 lineage；
- failed build：已完成对象的候选表和 lineage 一起清理，当前 published 不受影响；
- GC：继续保护 current 与 current.previous；只有物理表成功清理后，才在幂等元数据事务中删除对应 lineage 并写 purge tombstone；
- GC 失败：不影响已经完成的 publish/rollback，不提前删除受保护 lineage，重试必须收敛。

新版本完整性丢失必须 fail-closed 为 `snapshot_corrupt/lineage_incomplete`，不能降级查询旧数据或返回部分字段。旧版本没有 lineage 是受支持的兼容状态，不等同于损坏。

### 3.8 API 契约

响应模型：

```text
ObjectLineageResponse
  state: available | unavailable
  reason_code: null | lineage_not_recorded
  source / object / display_name / object_key / key_token
  dataset_version / object_version / template_version
  binding_hash / binding_status / map_batch_id
  fields[]:
    property / display_name / final_value
    state: available | unavailable
    reason_code: null | property_unmapped | join_target_missing | source_evidence_unavailable
    steps[]
    inputs[]:
      role / source_table / source_column / source_pk
      source_value / extract_batch_id / join
  warnings[] / generated_at
```

可选查询参数 `property` 只返回一个模板属性；不传则返回该对象记录的全部字段。字段顺序与 frozen template 一致，输入边按 `input_ordinal` 稳定排序。

HTTP/reason code：

| HTTP | reason_code | 语义 |
| --- | --- | --- |
| 401/403 | `unauthorized` / `token_not_configured` | 复用现有控制台数据访问纪律 |
| 404 | `object_not_found` / `field_not_found` / `record_not_found` | published snapshot 中无对应对象、字段或新血缘版本记录 |
| 409 | `dataset_not_published` / `snapshot_corrupt` / `lineage_incomplete` | 当前快照不可安全解析 |
| 422 | `lineage_key_invalid` | key token 不是规范 64 位 SHA-256 |
| 500 | `lineage_query_failed` + `error_id` | 安全内部错误，不返回 SQL/物理表/traceback |

兼容状态：published object 的 `lineage_schema_version=NULL` 时返回 `200 state=unavailable, reason_code=lineage_not_recorded`，不伪造空字段、不要求重建即可继续浏览旧对象数据。

API 必须在同一个只读事务中解析 published snapshot、object version 和 lineage；并发 publish 时返回完整旧版或完整新版，不能混合版本。

### 3.9 数据治理与访问记录

本里程碑不新增网络安全、TLS、RBAC 或凭据轮换能力；仅复用现有控制台访问和数据治理规则：

- endpoint 复用 raw 级 Bearer 纪律，因为响应含 raw 源值；
- 使用 frozen template 与 binding/source classification 对 final/source/before/after/source_pk 逐项服务端脱敏；
- 敏感或未分类值显示遮罩，但表名、列名、规则下标、批次和版本仍可用于追溯；
- 访问审计复用 `resource_type=object`，resource 只记 `field_lineage:{object}:{key_token 前缀}`；
- 审计不记录业务键原文、源值、响应、SQL、Token、规则正文或 traceback；
- Mock/Demo 使用合成值并持续显示非生产标识。

### 3.10 有界性与兼容性

- 单次只查询一个对象记录；字段数以 frozen template 为界；
- `property` 过滤在 SQL 层完成；不允许客户端提交 SQL、表名、列名或 dataset version；
- 每字段输入边上限由模板 derived 条件上限决定，超过模型上限在模板校验时失败；
- 响应值证据有明确大小上限，API 不返回 raw 全行；
- `ObjectRowsPageResponse.lineage_refs` 是新增字段，不改变现有 rows/columns/分页语义；
- `/`、`/v0`、`/v1`、MCP、Preview、quarantine、旧库和便携包行为必须无回归。

## 5. 前端交互

入口放在现有 Data → 对象数据表，不新增顶层导航：

1. 选择 source 和对象，加载当前 published 对象记录；
2. 点击行内“查看血缘”，打开只读抽屉；
3. 点击字段，展开 read/join/map/coerce/derived 步骤和 raw 输入证据。

抽屉固定展示：

- 当前 published dataset/object/template/binding/map batch 身份；
- 对象业务键和 key token 短摘要；
- 字段最终值、trace 状态和明确 unavailable 原因；
- 时间线式转换步骤；
- raw 表/列、源记录键、抽取批次和 join 关系；
- 脱敏/截断标志及“血缘证明系统处理事实，不证明源字典语义”的说明。

状态必须覆盖：

```text
idle / loading / available / unavailable(old dataset) / empty fields
unauthorized / not published / record missing / corrupt / unknown error / stale
```

切换 source、对象、分页、搜索、行或 published dataset 后，旧结果立即 stale/关闭；使用 `AbortController + request generation`，迟到响应不得覆盖新选择。加载期间禁用重复请求，错误可在原抽屉重试。

Mock 至少覆盖 direct+map、join、derived rule、derived default、复合键、敏感值遮罩、旧版本无 lineage、snapshot corrupt 和未知错误。

## 7. 测试矩阵

### 7.1 纯转换与来源

- direct 字段的 raw/final 值与现有 apply 结果一致；
- map 命中记录 before/after，enum/type 顺序与 M3 契约一致；
- int/decimal/money/bool 转换保留类型，不用字符串比较；
- derived 多规则首命中、default、unmatched、非法枚举和多条件输入；
- 单锚字段、join 字段、同目标表多个 FK、多表同名列、join target 缺失；
- 锚表/目标表单主键和复合 DDL 主键、各自抽取批次；
- 内部 provenance 列不进入对象 output、Preview diff、quarantine raw 或 MCP 响应；
- 正式 apply 与 Preview 对同一输入的既有状态/值/issue 完全一致。

### 7.2 存储与原子性

- 每个 mapped 对象行 × 每个模板属性恰好一个字段节点；
- derived 多条件产生稳定 input ordinal；unmapped/join missing 有明确节点；
- 规范键对同值稳定、类型变化敏感、键序按 template 固定、复合键无歧义；
- BLOB/超长文本只留 hash/preview/length；日期/Decimal/null 可重复序列化；
- 候选表 insert、字段节点 insert、输入边 insert、count 校验任一点失败均全部回滚；
- 熔断、重复业务键、类型失败和 quarantined 行不产生对象 lineage；
- 重试生成新 version，不覆盖旧 lineage；重复 migration 和 freeze trigger 生效。

### 7.3 数据集生命周期

- 新候选缺字段节点、count 错误、version/hash/batch 不一致不能 ready/publish；
- 任一对象失败时 current published 对象及 lineage 完全不变；
- publish 前后 API 只见完整旧版或完整新版；
- rollback 恢复 previous 的对象值和对应 lineage；
- 旧版 `lineage_schema_version=NULL` 可浏览/回滚并返回 `lineage_not_recorded`；
- current/current.previous 的候选表与 lineage 均受 GC 保护；更老 retired 成对清理；
- DROP 或 tombstone 失败时不影响 publish，重试收敛且不误删受保护证据；
- stale building recovery 同时处理候选表和 lineage 残留。

### 7.4 API 与数据治理

- key token 正常、大小写/长度/非 hex 非法、复合键定位和 record not found；
- unknown object/property、无 published、snapshot corrupt、lineage incomplete、内部异常；
- `property` 只返回目标字段，未传时按模板顺序返回全部字段；
- 响应版本与 published snapshot、object version、binding hash、map batch 完全一致；
- 敏感 final/map before-after/source value/source pk 均遮罩；未分类源值不明文；
- 表/列、规则下标、版本、批次可见，截断/脱敏显式标注；
- 审计只记录允许的摘要字段，不包含业务键、源值、SQL、Token 或 traceback；
- 同一只读事务并发 publish 压测不产生混合版本或部分 fields。

### 7.5 前端与 E2E

- 对象表每行 lineage ref 正确配对，翻页/搜索/刷新不串行；
- 单键和复合键对象均能三次点击打开目标字段；
- direct/map/join/derived/default 时间线正确；
- unavailable 原因、敏感遮罩、值截断和版本身份清楚可见；
- 401/403/404/409/422/500、空数据、旧版本、迟到响应、重复点击与重试；
- published 切换后旧抽屉不会继续显示为当前；
- 页面无修改 binding、改写 lineage、重放 apply 或跳转任意 raw 表的旁路；
- Mock/Real 使用同一生成类型，`/`、`/v0`、`/v1` 和 M3 Preview 无回归。

## 9. 风险与控制

| 风险 | 控制 |
| --- | --- |
| trace 与真实转换分叉 | 在 `mapping_transform` 实际 read/map/coerce/derived 分支记录步骤；一致性测试比较最终值 |
| join 只能看到值，找不到目标 raw 行 | SelectPlan 同时投影锚/目标主键、FK 和各自 batch；内部别名碰撞测试 |
| 候选表成功而 lineage 部分失败 | 候选表、字段节点、输入边和 count 使用同一显式事务 |
| 复合键塞入单 path segment 产生歧义 | frozen key canonical JSON + SHA-256 opaque token；对象页由服务端返回 ref |
| 旧数据集无血缘被误判为坏数据 | `lineage_schema_version=NULL` 明确建模，200 `lineage_not_recorded` |
| 新数据集血缘丢失却返回部分结果 | 行数×属性数门禁、版本一致性校验和 `lineage_incomplete` fail-closed |
| 血缘表体积过快增长 | 只为 mapped 字段存节点；不复制 raw 全行；BLOB/长值只存摘要；随 retired GC |
| 敏感值经 source_pk/steps 泄漏 | frozen classification 对所有值证据统一出口脱敏，unknown fail-closed |
| 并发 publish 导致对象和血缘混版 | 同一只读事务解析 published snapshot 并按 dataset/object version 查询 |
| GC 误删可回滚证据 | current + current.previous 同时保护；物理清理成功后才做幂等 lineage tombstone |
| 三次点击只在 Mock 成立 | 真实 API E2E 从对象表行入口到字段 source/rule/batch 做可见断言 |

## 10. 明确非目标

- 不为 Preview 持久化血缘，不保存临时草稿 trace；
