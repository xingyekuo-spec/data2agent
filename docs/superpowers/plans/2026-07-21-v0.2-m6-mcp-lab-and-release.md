## 1. 目标

M6 完成 v0.2 最后一个纵向切片：用户在 Vue Console 内完成 MCP 对象查询、指标查询和“说”档建议卡生成，并能理解每条 evidence 引用了哪次查询。同时完成 `/v1` 在源码、Docker 和便携包中的真实分发闭环。

完成后，用户不打开 SQLite、不使用命令行 MCP 客户端，也能回答：

1. `query_objects` 和 `query_metrics` 支持哪些目标与参数；
2. 本次调用是否成功、耗时多少、返回了什么结构化结果和原始 JSON；
3. 哪些字段已脱敏，哪些 binding/metric 仍为 draft，当前口径有什么 caveat；
4. 建议卡引用了哪些当前进程内查询 ID，每条 evidence 对应哪次查询；
5. 建议卡只是“说”档输出，没有执行 ERP 写回或其他“做”档动作；
6. 当前 query ID 只在 Console 进程内有效，为什么重启后不能继续引用；
7. Vue `/v1` 在开发、FastAPI 源码运行、Docker 和 Windows 便携包中的安装状态是否可信。

M6 关闭同时代表 v0.2 发布门禁通过。任一八页面、真实性、安全、兼容或分发必选项失败，M6 保持进行中或阻塞，不以“后续补充”关闭。

## 2. 范围

### 2.1 本里程碑包含

- 冻结 MCP 对象查询、指标查询、建议卡、evidence、错误和进程级边界的前后端契约；
- 复用 `QueryService` 建立 Console 进程内长生命周期查询服务，使 query ID 可被后续建议卡引用；
- 保持 `POST /api/debug/mcp-call` 只读白名单，仅允许 `query_objects` / `query_metrics`；
- 实现独立 `POST /api/gateway/proposals`，调用“说”档 `propose_action`，拒绝无效或不可追溯 evidence；
- MCP Lab 对象查询与指标查询参数表单、结构化结果、原始 JSON、耗时、错误、脱敏和口径警示；
- 建议卡表单、当前查询选择、claim 编辑、结构化卡片和 evidence 展开；
- `useMcpLabStore` 的请求竞态保护、内存查询历史、错误保留和刷新边界；
- Mock 场景、OpenAPI 快照、生成类型、service、组件测试和 Real/Mock E2E；
- Settings 只读回归和八个主页面的 v0.2 集成验收；
- FastAPI `/v1` 静态挂载、SPA fallback、dist 缺失诊断；
- Docker 和 Windows 便携包包含 Vue dist 的构建/检查流程与运行说明。

### 2.2 明确不包含

- “做”档动作、审批流、ERP 写回或建议卡一键执行；
- 把 `propose_action` 加入 Jinja `/api/debug/mcp-call` 白名单；
- 在线 mapping 编辑、自动 verified/certified 或指标现场校准；
- v0.3 的主体隔离、浏览器会话隔离、不可预测 query ID、result digest 或 evidence 持久化；
- dataset/object version、字段级血缘、影子发布和原子切换；
- 多租户、SSO/RBAC、PostgreSQL 迁移或跨进程分布式 session；
- 用前端重新脱敏或重新计算指标口径。

## 4. 不可回退的设计决策

### 4.1 v0.2 query ID 只承诺 Console 进程级边界

Console 创建一个与当前 `landing/templates/source/max_tier` 配置签名绑定的长生命周期 `QueryService`。同一进程、同一配置签名内的成功查询可被建议卡引用；配置重载、landing/template/source 变化或进程重启必须清空查询日志。

MCP Lab 必须持续显示：“query ID 仅在当前 Console 进程内有效；服务重启或配置变更后需重新查询”。不得使用“永久证据”“会话隔离”或“跨用户可信”文案。主体、浏览器会话和结果摘要级 evidence 属于 v0.3。

### 4.2 Vue 查询复用只读调试入口，建议卡使用独立入口

- `POST /api/debug/mcp-call`：只允许 `query_objects` / `query_metrics`，Jinja 与 Vue 共用只读工具语义；
- `POST /api/gateway/proposals`：唯一建议卡入口，只调用 `propose_action`；
- 两个端点必须使用同一个进程内 `QueryService` 实例，否则 query ID 无法关联；
- Jinja debug 页面不得出现 `propose_action`，`_MCP_TOOLS` 白名单不得扩大；
- MCP HTTP fallback 若不能共享 query log，不得返回一个看似可用于建议卡的 query ID。实现必须选择 fail-close，或把远端调用与 proposal 明确绑定到同一远端会话后再开放；M6 默认以本地进程内服务为 Vue Lab 的可信路径。

### 4.3 建议卡是“说”档结构化输出，不是动作入口

建议卡请求只接受模板声明的 object/action、非空 conclusion 和至少一条 `{claim, query_id}`。每个 query ID 必须存在于当前进程查询日志中。响应展示 `tier/governance/caveats/evidence`，不创建 Run、不修改对象/隔离/水位，也不提供“执行建议”按钮。

### 4.4 前端只展示服务端治理结果

对象敏感字段必须在 `QueryService` 返回前脱敏；指标 draft/caveat、binding 状态和 masked fields 来自响应。表格与原始 JSON 使用同一个响应对象，前端不得保留隐藏的未脱敏副本，也不得自行移除 caveat。

查询历史仅保存在 Pinia 内存中，不写 `localStorage`。Token 继续只在当前标签页 `sessionStorage`。页面刷新后本地 evidence 展开材料可以消失，并明确提示重新查询；不得伪造恢复。

### 4.5 错误不能伪装为空结果

参数错误、未知对象/指标、对象未物化、query ID 失效、治理档位不允许、MCP 不可用和限流必须是可区分的结构化失败。页面保留上一次成功结果并显示刷新/执行失败标记，不能把失败渲染成 0 行或正常空态。

错误正文不得包含 Token、DSN、SQLite 路径、完整上游响应、traceback 或任意 SQL。内部错误使用固定摘要和可选 `error_id`。

### 4.6 `/v1` 分发以 FastAPI 实际运行结果为准

- 源码/便携包：FastAPI 检测打包后的 dist 并挂载 `/v1`；`/v1/*` 深链回退到 `index.html`；
- dist 缺失：`/v1` 返回明确、可诊断的未安装页面和非成功状态，不回落到 Jinja `/` 或 `/v0`；
- `/api`、`/`、`/v0`、`/config`、`/logs`、`/debug` 路由优先级不受 SPA fallback 影响；
- Docker/便携包构建必须在产物检查中证明 `index.html` 和所有引用资源存在，运行时不依赖 CDN；
- Vite 开发服务器通过 `/api` proxy 的结果不能替代 FastAPI 挂载和便携包验收。

## 5. 契约目标

M6-T01 先固定以下语义，允许字段命名按现有模型微调，但不得退回任意裸 JSON + 自由文本判断。

### 5.1 查询请求

```text
McpCallBody
├─ tool: query_objects | query_metrics
└─ params: JsonObject
```

`query_objects` 参数：`object? / filters? / order_by? / desc? / limit?`；`query_metrics` 参数：`metric? / group_by? / limit?`。后端继续负责模板白名单、属性/维度校验和 limit 上限。

### 5.2 查询公共元数据

```text
McpQueryMeta
├─ query_id: string | null
├─ tool: query_objects | query_metrics
├─ target: string
├─ row_count: integer | null
├─ duration_ms: integer
├─ masked_fields: string[]
├─ warnings: string[]
└─ evidence_scope: process
```

目录查询没有可引用 query ID 时必须返回 null，并在 UI 禁止选为 evidence。只有实际数据查询成功后产生 query ID。

### 5.3 对象和指标结果

对象结果保留 object/display_name/rows/meta；指标结果保留定义、implemented、unit/group_by/rows/meta。M6 可在兼容原结果的前提下补充公共 meta，但不能删除 MCP 现有调用方依赖字段。原始 JSON 必须与结构化视图同源。

### 5.4 建议卡

复用现有 `ProposalRequest/ProposalResponse`，并冻结：

- evidence 至少一条，claim 非空；
- query ID 不存在或已因配置/进程重置失效时返回具名 409/422；
- tier 超过部署上限时返回 403/409，不执行任何副作用；
- response 中每条 evidence 带 query_id/tool/target/at；
- v0.2 不宣称包含 result digest，UI 展开使用当前内存查询结果；
- `governance` 明确“说档、未执行写操作”。

### 5.5 安全错误

```text
McpLabError
├─ detail: string
├─ reason_code: invalid_params | unknown_target | not_materialized |
│               query_expired | tier_forbidden | rate_limited |
│               mcp_unavailable | execution_failed
├─ tool: string | null
├─ retryable: boolean
└─ error_id: string | null
```

FastAPI 参数校验仍可使用标准 422；MCP/业务错误使用上述安全模型。前端只按 status/reason_code 分支，不解析中文 detail。

## 6. 后端实施要求

- 在 Console `state` 中缓存 `QueryService` 和配置签名；配置变化时原子替换并清空旧引用；
- 并发请求不得产生重复 query/proposal ID 或破坏有界日志；需要为序列与日志访问加锁，或采用等价线程安全实现；
- Console 查询和 proposal 必须共享实例；测试覆盖配置重载、进程级过期和容量淘汰；
- 目录查询、数据查询、未物化、未知目标、draft 指标和敏感字段全部覆盖；
- `gateway/proposals` 不写业务数据，不创建 Run，不调用任何“做”档动作；
- 统一异常映射，不向客户端透传 `urllib`/SQLite/traceback/路径/Token；
- 管理 API 继续服从 Console Token；首次配置或 landing/template 不可用时诚实返回 409；
- 保持 MCP HTTP 自身 Bearer、限流和审计行为不回归；
- OpenAPI 中移除 proposal 的 M6 501 stub 标记和 501 响应。

## 7. 前端实施要求

### 7.1 页面结构

- 顶部固定显示进程级 query ID 边界和“说档不执行写操作”说明；
- 对象查询 tab：目录选择、filters JSON/结构表单、排序、limit、执行；
- 指标查询 tab：指标、group_by、limit、draft/caveat 提示、执行；
- 查询结果：摘要、结构化表格、masked fields、warnings、耗时、query ID、原始 JSON；
- 建议卡 tab：对象/action、结论、从当前成功查询选择 evidence、逐条 claim；
- 建议卡结果：结论、档位、治理文案、caveats、可展开 evidence；
- 空态、参数错误、未物化、MCP 不可达、query 过期和陈旧成功数据都必须可区分。

### 7.2 Store

`useMcpLabStore` 至少维护：

- 当前对象/指标请求状态；
- 最近一次成功结果与原始同源对象；
- 当前进程内由本页面取得的成功查询历史（有界）；
- proposal 请求状态和最近成功卡片；
- request sequence/AbortController，防止旧响应覆盖新参数；
- 配置/进程边界变化后的 history 清空提示。

组件卸载或详情关闭后不得把 Token、完整 filters、查询结果或 evidence 写入持久化存储。

## 13. 主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 每次查询新建服务导致 query ID 无法引用 | 配置签名绑定的长生命周期 `QueryService` + 同实例 proposal |
| 多请求并发产生重复 ID/日志损坏 | 锁或等价线程安全序列；并发测试 |
| 远端 MCP fallback 返回不可引用 ID | Vue Lab 默认进程内 fail-close；未共享会话不得宣称可 evidence |
| 进程级 ID 被误解为永久证据 | 页面固定 scope 提示；重启/配置变更清空并拒绝 |
| proposal 被当作执行动作 | 独立说档入口、无 Run/写入、无执行按钮、治理文案 |
| 前端 JSON 绕过脱敏 | 结构视图与 JSON 同一服务端响应，不保留未脱敏副本 |
| MCP 错误泄露路径/上游正文 | 结构化 reason_code + 固定摘要 + error_id |
| Vite 开发成功掩盖实际分发缺失 | FastAPI `/v1`、Docker、portable 分别验收 |
| SPA fallback 吞掉 API/Jinja | 路由优先级与 `/api`、`/`、`/v0` 回归测试 |
| 便携包只复制 index 未复制 hash 资源 | 解析 index 资源并逐项存在性检查，运行态 HTTP 验证 |
