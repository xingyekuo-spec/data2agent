## 1. 目标

M5 把 M4 已经可浏览的数据和 Run step 证据，推进到“能解释为什么失败、当前服务是否受影响、模板口径是否可信”的只读验证工作台。完成后，用户不打开 SQLite、不解析日志，也能回答：

1. 哪些对象存在未处理隔离，数量、最近批次和最近发生时间是什么；
2. 每条隔离记录的业务键、失败原因、原始值预览、批次和来源是什么；
3. 当前隔离率是否超过熔断阈值，是否导致对象层继续服务上一稳定结果；
4. 某个对象若重新映射，影响范围是整个对象而不是单行；
5. 模板包包含哪些对象、属性、敏感标记、业务键和来源；
6. 每个 binding 的 `draft / verified / disabled` 状态、field map、key map、derived 规则和 watermark 是什么；
7. 指标定义是否仍为 draft，尤其是 MVP 相关指标如 `quote_response_hours` 是否已现场校准；
8. 页面状态继续遵守 M2–M4 的规则：unknown 不变绿、失败不变空数据、Mock/Real 可辨。

M5 完成后，M2 中的隔离区和模板占位页进入 Real 可验收状态；M6 MCP Lab 仍保持占位，不提前实现。

## 2. 范围

### 2.1 本里程碑包含

- 固定隔离记录、隔离分组、模板对象、模板指标和对象级 retry 的前后端契约；
- 增强 `GET /api/quarantine`：保持数组正文兼容，同时增加分页、筛选、总数和更完整字段；
- 新增隔离分组/摘要接口，用于按对象展示未处理数量、隔离率、阈值、最近批次和服务状态；
- 复用 M4 的 JSON-safe、脱敏、截断和服务端分页能力展示隔离 raw 预览；
- 明确对象级 retry 语义：只允许重新映射整个对象，必须二次确认，只读模式禁用，执行后必须进入统一 Run + step 证据；
- 实现 `GET /api/templates` 真实只读响应，暴露对象、属性、敏感标记、binding、field map、key map、derived、枚举和 watermark；
- 新增模板指标只读接口或等价契约，展示指标 `draft / certified / deprecated` 状态、公式、粒度、维度和 caveats；
- 实现 Vue 隔离页和模板页，包括筛选、分组、详情抽屉、规则展示、空/错/未知状态；
- 更新 OpenAPI、生成类型、service、store、Mock fixture 和浏览器验收；
- 补齐后端契约、安全、分页、只读副作用、对象级 retry 观测和前端组件测试。

### 2.2 明确不包含

- 在线编辑、保存、发布或回滚 mapping/binding；
- 自动将 binding 或指标从 `draft` 改为 `verified/certified`；
- 单行隔离重试、单行修复、删除隔离记录、批量标记已处理；
- raw 原文 unmask、数据库下载、任意 SQL 或任意列选择；
- mapping preview、临时草稿映射、正式对象版本发布；
- v0.3 的 dataset/object version、原子发布、回滚和一键验收动作；
- M6 MCP Lab 的工具调用、建议卡和 evidence 会话能力。

## 4. 核心实施决策

### 4.1 隔离区是证据视图，不是数据修复器

M5 默认只展示未处理隔离记录。页面可以解释原因、分组、影响和下一步动作风险，但不得提供单行修复、删除或“标记已处理”。`resolved_at` 仅用于筛选未来兼容，不在 M5 提供写入口。

### 4.2 `/api/quarantine` 保持数组正文兼容

延续 M1/M4 的兼容策略：`GET /api/quarantine` 响应正文仍是数组，分页总数放在 `X-Total-Count`。新增字段只能做加法扩展，不改掉既有 `id/source/object/keys_json/reason/created_at`。

### 4.3 raw 预览复用 M4 安全内核

隔离 raw 预览来自 `d2a_quarantine.raw_json`，但展示前必须执行 JSON-safe、64 KiB 预算、敏感字段脱敏和截断标记。表格和 JSON 视图必须同源，不能让 JSON 绕过脱敏。

### 4.4 隔离率和熔断阈值不能猜成正常

隔离率优先用最近 apply object step 的 `quarantined / rows_in`。缺少 step、rows_in 为 0 或历史数据不可关联时返回 `unknown/null`，页面显示“不可检测”，不得显示 0% 或绿色。默认熔断阈值读取 `DEFAULT_BREAKER_THRESHOLD`，未来有配置时再以配置覆盖。

### 4.5 对象级 retry 是受保护写操作

路线图要求对象级 retry 必须提示“会重新映射整个对象”。M5 若启用 Vue retry，必须满足：

- 只允许对象级，不允许单行 retry；
- 只读模式或未加载 config 时按钮禁用并显示原因；
- 点击后先展示影响范围、当前未处理隔离数、阈值和“会重建整个对象”的确认文案；
- 确认后复用后端 connect 映射引擎，不能绕过白名单、熔断和错峰/只读策略；
- 成功、熔断或失败都必须写入统一 Run + step，可从运行页追踪；
- 页面不解析自由文本判断结果，只读结构化响应和 Run detail。

如果实现中发现 retry 需要更大写操作授权，必须拆成 M5b 或后续里程碑，不阻塞 M5 的只读展示。

### 4.6 模板页只读，不做现场校准

模板页展示元模型真实内容和校准状态，但不提供编辑器、发布按钮、自动 verified/certified，也不把 draft 状态降噪隐藏。对象、binding 和指标的 draft 都是用户需要看到的治理事实。

## 5. 契约草案

M5-T01 先在 `contracts.py` 固定契约，再实现后端和前端。字段命名允许按现有风格微调，但必须保留本节语义。

### 5.1 QuarantineRecord 加法扩展

```text
QuarantineRecord
├─ id: integer
├─ source: string
├─ object: string
├─ keys_json: string | null        # legacy 兼容
├─ keys: JsonObject | null         # 解析失败为 null + warning
├─ reason: string
├─ raw: JsonObject | null          # 已脱敏、已截断、JSON-safe 的预览
├─ truncations: FieldTruncation[]
├─ batch_id: string | null
├─ created_at: datetime           # 新响应按带时区 ISO 8601
├─ age_seconds: integer | null
└─ warnings: string[]
```

`raw` 不得包含 Token、SQL、traceback 或未脱敏敏感字段。`keys_json` 保留给旧消费方，前端优先读 `keys`。

### 5.2 QuarantineGroup

```text
QuarantineGroup
├─ source: string
├─ object: string
├─ display_name: string | null
├─ pending: integer
├─ latest_created_at: datetime | null
├─ latest_batch_id: string | null
├─ latest_reason: string | null
├─ quarantine_rate: number | null
├─ breaker_threshold: number
├─ rate_state: ok | warning | tripped | unknown
├─ serving_state: fresh | stale | not_materialized | unknown
├─ latest_apply_run_id: integer | null
├─ object_rows: integer | null
├─ mapped_at: datetime | null
└─ warnings: string[]
```

`serving_state=stale` 表示对象层仍可服务但不是当前 raw 的完整新结果；不能显示为健康。

### 5.3 隔离接口

```text
GET /api/quarantine?source&object&reason&limit&offset
  -> QuarantineRecord[] + X-Total-Count

GET /api/quarantine/groups?source
  -> QuarantineGroup[]
```

`limit` 默认 50，上限 100；`offset` 默认 0。筛选全部参数化，不拼接用户输入到 SQL。

### 5.4 对象级 retry 响应

现有 `POST /api/actions/retry` 可作为入口，但 M5 必须补齐结构化证据：

```text
RetryActionResult
├─ executed: true
├─ object: string
├─ total: integer
├─ mapped: integer
├─ quarantined: integer
├─ status: ok | aborted
├─ run_id: integer
├─ step_id: integer
└─ detail_path: string
```

熔断返回 409 + `HttpError`，但对应 Run/step 仍必须记录 `aborted` 和结构化度量。

### 5.5 TemplateObject 加法扩展

```text
TemplateObject
├─ object / display_name / description / domain / keys
├─ source_of_truth: string
├─ properties: TemplateProperty[]
├─ bindings: TemplateBinding[]
├─ knowledge_refs: string[]
├─ materialized: TemplateMaterialization
├─ quarantine_pending: integer
└─ warnings: string[]

TemplateProperty
├─ name / type / desc / sensitive
├─ ref: string | null
└─ enum_values: string[]

TemplateBinding
├─ source / tables / status / key_map / field_map / watermark / notes
├─ enabled: boolean
└─ derived: Record<string, DerivedField>
```

`status=disabled` 的 binding 必须可见但明确不参与抽取/映射/查询。

### 5.6 TemplateMetric

```text
GET /api/templates/metrics
  -> TemplateMetric[]

TemplateMetric
├─ metric: string
├─ display_name: string
├─ status: certified | draft | deprecated
├─ formula: string
├─ grain: string[]
├─ dimensions: string[]
└─ caveats: string
```

指标 draft 不能被视为错误，但必须显式可见。

## 6. 后端实施要求

### 6.1 存储与查询

- 不新增破坏性迁移；优先复用 `d2a_quarantine` 和 M4 `d2a_run_step`；
- `keys_json/raw_json` 解析失败不得 500，记录 warning 并返回 null；
- 分组查询限定在模板对象和已知 source 范围内；
- 所有筛选参数化，标识符只来自模板/配置白名单；
- 浏览隔离记录不得修改 quarantine/raw/object/watermark/run 状态。

### 6.2 服务状态与旧版本

- `mapped_at`、object rows、raw 最新时间优先复用 M4 data_browser/observability 工具；
- raw 新于 object 或最近 apply aborted/failed 时，组状态必须显示 stale/warning；
- 缺少证据时显示 unknown，不回退为 healthy；
- `latest_apply_run_id` 来自结构化 Run/step，不解析 detail 文本。

### 6.3 模板读取

- `GET /api/templates` 从 `TemplatePack` 构造，不读前端 fixture；
- properties 必须带 `enum_values/ref/sensitive`；
- binding 必须带 `derived` 原始决策表和 `enabled`；
- metrics 从 `pack.metrics` 构造；
- 模板加载失败按既有 `require_pack` 语义返回 409，不返回空列表伪装成功。

## 7. 前端实施要求

### 7.1 隔离页

页面至少包含：

- 顶部摘要：未处理总数、涉及对象数、超过阈值对象数、最近隔离时间；
- 对象分组表：对象、来源、未处理数、隔离率/阈值、服务状态、最近批次、最近原因；
- 记录表：业务键、原因、批次、时间、来源；
- 详情抽屉：keys、raw 安全预览、truncations、warnings、关联运行入口；
- 对象级 retry 入口：只读模式禁用；启用时必须二次确认影响范围；
- 空态：隔离区为空时显示正常空态，但不得影响 Dashboard/Pipeline 对其他 unknown 的判断。

### 7.2 模板页

页面至少包含：

- 对象列表：对象、领域、来源、key、属性数、binding 状态、物化/隔离概况；
- 对象详情：属性表、敏感标记、enum/ref、source_of_truth、knowledge_refs；
- binding tab：按 source 展示 status、tables、key_map、field_map、derived、watermark、notes；
- 指标 tab：metric、status、formula、grain、dimensions、caveats；
- draft/disabled 明确标识，不用绿色表达“可忽略”；
- 所有内容只读，不出现编辑、保存、发布、verified/certified 切换控件。

### 7.3 Store 与请求状态

- `useQuarantineStore` 和 `useTemplatesStore` 是页面唯一数据所有者；
- 首次失败进入 error；刷新失败保留旧数据并显示 refreshError；
- 分组、记录、详情请求各自有代际保护，旧响应不得覆盖新筛选；
- 不加入 M3 全局 5 秒轮询；隔离/模板由用户显式刷新。

## 8. Mock、E2E 与安全场景

### 8.1 Mock 场景

至少扩展以下既有场景：

- healthy：隔离为空、模板全部 draft 可见；
- quarantine-pending：多个对象有不同原因和批次；
- apply-circuit-broken：隔离率超过阈值、对象层 stale、retry 确认文案可见；
- empty-install：模板/隔离不可用状态诚实显示；
- unknown-error：刷新失败保留旧数据；
- token-invalid：写动作被认证拦截，页面不伪造成功。

### 8.2 Real E2E

Real 临时库验收至少覆盖：

1. 制造一条 enum/业务键隔离并在页面可见；
2. 分组表显示对象、未处理数、隔离率、阈值和批次；
3. 隔离详情 raw 预览与 JSON 同源脱敏/截断；
4. apply 熔断时页面显示对象层使用旧结果/stale；
5. 对象级 retry 有二次确认，且执行后可在 Runs 看到结构化 Run/step；
6. 模板页显示 5 个对象、属性、sensitive、enum/ref、binding 状态；
7. derived 决策表在 SalesOrder 可见；
8. 指标 draft 状态和 `quote_response_hours` caveat 可见；
9. 浏览隔离/模板不改变 raw/object/watermark/quarantine；
10. `/v0`、Jinja 管理页、M4 运行/审计/数据页不回归。

## 11. 退出门禁

M5 只有同时满足以下条件才能从“待开始/进行中/待验收”改为“已完成”：

- [ ] 隔离记录可按 source/object/reason 分页筛选，并保持数组正文兼容；
- [ ] 隔离分组能显示未处理数、隔离率、阈值、最近批次和服务状态；

## 12. 主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 隔离 raw 预览泄露敏感值 | 复用 M4 服务端脱敏与 JSON-safe；表格/JSON 同源 |
| 历史隔离缺少可关联 step | rate/serving_state 返回 unknown，不猜成 0% |
| retry 被误解为单行修复 | 文案和 API 都只允许对象级；确认框写明会重新映射整个对象 |
| retry 绕过 Run 观测 | M5-T05 必须补 Run+step；失败也可追踪 |
| 模板页膨胀成编辑器 | 全部控件只读；无保存/发布/verified 切换 |
| draft 状态被视觉弱化 | draft/disabled 使用明确状态标签和筛选 |
| 指标校准被遗漏 | metrics 独立 tab/接口进入退出门禁 |
| M6 MCP Lab 提前抢范围 | 本文不实现工具调用或建议卡；只保留现有占位 |
