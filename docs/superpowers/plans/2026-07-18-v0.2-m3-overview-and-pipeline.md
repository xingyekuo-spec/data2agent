## 1. 目标

把 M2 中可演示的 Dashboard、管道页和 Mock 场景接到可解释的真实观测数据上，使非技术用户不查看 SQLite 或自由文本日志，也能在 30 秒内回答：

1. 整条 `ERP → 抽取 → 推送 → Raw → 映射 → 对象层 → MCP` 链路当前是否健康；
2. 如果不健康，问题发生在哪个节点；
3. 当前是从未运行、正在运行、最近失败、数据陈旧，还是仍在使用上一稳定对象结果；
4. raw、对象层和隔离区各有多少数据，这些数字分别代表什么；
5. 页面展示的应用、模板和数据是什么版本，更新时间是什么；
6. 页面信息来自 `MOCK / DEMO / REAL` 中的哪一种环境。

M3 完成后，`GET /api/pipeline` 不再返回 501，`GET /api/overview` 提供 Dashboard 所需的真实聚合；M2 的 Mock 场景继续使用同一契约、store 和页面组件。

## 4. 核心实施决策

### 4.1 状态必须由结构化事实计算

新增 `data2agent/console/observability.py`，集中完成查询和状态计算。路由只负责鉴权、调用和响应序列化；页面只展示后端给出的领域状态，不在 Vue 中重复推导另一套业务规则。

允许使用的事实来源：

- `d2a_sync_run.status/started_at/finished_at/tables/rows`；
- 新增的 `d2a_sync_run.run_type`；
- `d2a_sync_state` 的水位和最近批次；
- `d2a_audit_log.action/ts/rows/duration_ms/batch_id`，不得解析 `sql`；
- raw/object 表中框架生成的 `_d2a_*` 元数据列；
- `d2a_quarantine.resolved`；
- 模板和 binding 的结构化配置；
- `/api/services` 使用的显式健康探测；
- 安装包元数据和模板包版本。

`detail` 只允许作为已记录的错误摘要原样、安全截断后展示，不得通过关键词解析它来决定状态或运行类型。

### 4.2 `unknown` 是一等状态

当证据不存在、查询失败、跨机器状态不可见、版本尚未实现或探测超时时，返回 `unknown` 或 `null` 并说明原因。不得替换为：

- `healthy`；
- 数字 `0`；
- 当前时间；
- 假版本号；
- 正常空列表。

请求失败继续使用 M2 的请求 `error`；成功返回但不可检测才使用领域 `unknown`。

### 4.3 M3 只补最小运行分类，不提前实现 M4 Run

对 SQLite 做幂等、兼容式扩展：

```text
d2a_sync_run.run_type: sync | apply | reconcile | ingest | NULL
```

- 用 `PRAGMA table_info` 检测后再 `ALTER TABLE ... ADD COLUMN`；
- 旧记录保持 `NULL`，前端显示“类型未知”，不能一律回填为 sync；
- `start_run` 要求调用方显式传入 `run_type`；
- incremental sync、apply、reconcile 的所有调用点和测试同步更新；
- ingest 暂时继续以结构化 audit batch 表达，避免为每次 HTTP batch 复制一套不完整 Run；
- M4 在此基础上统一 `Run + steps`，M3 不新增半成品 step 表。

### 4.4 陈旧度使用配置，不写死业务 SLA

每个源的默认新鲜度阈值：

```text
freshness_threshold = max(2 × sync_every_seconds, 300 秒)
```

- 有源级显式阈值时优先使用显式值；
- `sync_every` 缺失或无法解析时不猜测阈值，返回 `unknown`；
- `stale` 表示数据事实落后，不等同于服务进程宕机；
- 所有响应同时返回 `observed_at` 或 `generated_at`，页面显示“截至何时”。

### 4.5 版本信息保持诚实

- `app_version` 使用 `importlib.metadata.version("data2agent")`；开发环境找不到包元数据时明确回退为 `unknown`；
- `template_version` 读取模板 pack 的结构化 `version`；
- `component_version` 可用于 MCP/console 等可检测组件；
- `dataset_version` 和 `object_version` 在 v0.3 前返回 `null`；
- “使用上一稳定结果”由 raw/object 时间差和最近 apply 结构化状态判断，不伪造对象版本号；
- 页面文案显示“版本尚未启用（v0.3）”，不能显示 `v0`、`latest` 或当前时间充当版本。

### 4.6 告警是聚合结果，不是 M3 新业务实体

M3 的当前告警由节点、服务、隔离数量和治理状态确定性生成：

- ID 由 `kind + node/source/object` 组成，刷新后稳定；
- 严重度为 `info | warning | critical`；
- 每条包含标题、原因、数据来源、发生/观测时间和可用的详情入口；
- 不建告警确认、静音、通知和历史表；
- 后端查询异常要形成不可检测告警，不能让告警区空白。

### 4.7 轮询只有一个所有者

`AppLayout` 启动共享观测 store，Dashboard、Pipeline 和 TopBar 只消费状态：

- 默认 5 秒轮询，与控制台规格一致；
- 同一请求未结束时跳过下一次，禁止并发堆积；
- 标签页隐藏时暂停，重新可见时立即刷新；
- 失败后保留上一次成功数据并明确标记“刷新失败/数据截至…”，按上限退避；
- 场景切换或认证恢复后立即刷新；
- 组件卸载和应用销毁时清理 timer/listener；
- 不允许每张卡片各自 `setInterval`。

## 5. API 契约

### 5.1 `GET /api/overview`

保持 M1/M2 已有字段兼容，在响应中追加具名结构：

```text
OverviewResponse
├─ 既有 landing / readonly / actions / sources / objects / needs_setup
├─ generated_at: datetime
├─ summary
│  ├─ raw_rows: integer | null
│  ├─ object_rows: integer | null
│  ├─ materialized_objects: integer
│  ├─ template_objects: integer
│  ├─ quarantine_pending: integer | null
│  ├─ last_run_at: datetime | null
│  └─ data_updated_at: datetime | null
├─ versions
│  ├─ app: string | null
│  ├─ template: string | null
│  ├─ dataset: string | null
│  └─ object: string | null
├─ binding_summary
│  ├─ verified: integer
│  ├─ draft: integer
│  └─ disabled: integer
├─ alerts[]
├─ recent_runs[]            # 最多 5 条，run_type 可为 null
├─ sync_trend[]             # 最近 24 小时，数量有上限
└─ count_notes[]            # 数量名称、口径、数据源
```

计数规则：

- `raw_rows` 是当前配置范围内、未逻辑删除的 raw 活跃行数之和；
- `object_rows` 是已物化 `obj_*` 表的行数之和；
- `materialized_objects / template_objects` 是覆盖率的分子/分母；
- `quarantine_pending` 只统计 `resolved = 0`；
- 标识符只能来自已加载配置/模板并经现有标识符校验，禁止接受用户 SQL；
- 任一聚合不可检测时返回 `null` 和告警，不能用 `0` 掩盖错误；
- 数据规模超出同步聚合预算时记录耗时并降级为可解释的未知，不引入无限扫描。

### 5.2 `GET /api/pipeline`

扩展现有契约，不改变已声明的节点和状态枚举：

```text
PipelineResponse
├─ generated_at: datetime
├─ overall_status: PipelineStatus
└─ nodes[]
   ├─ node: erp | extract | push | raw | mapping | objects | mcp
   ├─ status: unknown | idle | running | healthy | warning | failed | stale
   ├─ status_reason: string
   ├─ observed_at: datetime | null
   ├─ last_success_at / last_failure_at: datetime | null
   ├─ rows_in / rows_out / duration_ms: integer | null
   ├─ error: string | null
   ├─ version: string | null
   ├─ run_id: string | null
   ├─ source: string | null
   └─ detail_path: string | null
```

总体状态按明确优先级折叠：

```text
failed > stale > warning > running > unknown > idle > healthy
```

优先级只用于总体摘要；节点原始状态不能被总体状态覆盖。存在任何 `unknown` 时总体不得为 `healthy`。

### 5.3 时间兼容

- 新增的 `generated_at/observed_at` 必须带时区；
- legacy SQLite 无时区时间按服务器本地时区解释后序列化，并集中在一个转换函数中；
- 解析失败返回 `null` 并产生不可检测原因，不把当前时间当作原时间；
- M4 再统一迁移全部 legacy 时间字段，M3 不做破坏性数据库重写。

## 6. 七节点状态口径

| 节点 | 主要证据 | 状态规则摘要 | 不可见时 |
| --- | --- | --- | --- |
| ERP | 最近结构化 sync run、源配置 | 运行中为 `running`；最近失败为 `failed`；阈值内成功为 `healthy`；超阈值为 `stale` | 平台看不到中间机运行时 `unknown` |
| 抽取 | sync run 的表/行数/耗时 | 同上，显示 rows in/out 和 run ID；从未运行为 `idle` | 运行类别或时间不可判定为 `unknown` |
| 推送 | HTTP sink 配置、ingest audit batch、服务探测 | HTTP 批次成功为 `healthy`，失败证据为 `failed`；本地直写为 `idle` 并注明“不经过 HTTP 推送” | 缺少跨机器相关性时 `unknown` |
| Raw | raw 活跃行、最新 `_d2a_extracted_at`、sync state | 无数据且从未同步为 `idle`；阈值内为 `healthy`；超阈值为 `stale` | 元数据缺失/查询失败为 `unknown` |
| 映射 | 最新 apply run、隔离数、binding 状态 | apply 运行中/失败分别为 `running/failed`；draft 或隔离待处理为 `warning`；成功为 `healthy` | 从未 apply 为 `idle`，类别未知则 `unknown` |
| 对象层 | obj 表、`_d2a_mapped_at`、raw 最新时间、apply 状态 | 未物化为 `idle`；raw 新于对象或 apply 失败且旧表保留为 `stale`；同步为 `healthy` | 时间/表查询失败为 `unknown` |
| MCP | MCP health、对象层状态 | 服务失败为 `failed`；对象陈旧时为 `stale`；对象未就绪为 `idle`；服务和对象均正常为 `healthy` | 未配置或探测超时为 `unknown` |

额外约束：

- 最近失败之后若已有更新的成功，可以显示 `healthy`，但仍保留 `last_failure_at`；
- 正在运行优先展示本次 run 的 ID、开始时间和已知行数；
- 服务进程健康不等于数据健康；`/health` 为 200 不能覆盖数据 `stale`；
- “上一稳定结果”必须显示为 `stale` 或 `warning`，绝不能因旧对象表仍可查询而显示绿色；
- 错误摘要最长 500 字符，不能包含 Token、完整 SQL 或原始敏感行。

## 7. 前端交付设计

### 7.1 Dashboard

页面从上到下包含：

1. 四张摘要卡：对象层总行数、对象覆盖率、隔离待处理、最近运行；
2. 状态摘要：整体状态、最近数据更新时间、当前告警数量和旧结果提示；
3. 最近 24 小时抽取趋势；使用 ECharts 按需引入，不全量打包；
4. 对象分布；显示对象名、行数和占比，空数据不绘制假柱；
5. 最近 5 次运行；显示类型、来源、状态、行数、开始/结束时间；
6. 当前告警；按 critical/warning/info 排序；
7. 版本与治理：应用、模板、dataset/object 版本、binding 状态；
8. 数量口径说明和每个模块的数据来源/更新时间。

页面状态必须覆盖：loading、empty、error、unknown、running、healthy、warning、failed、stale。保留旧数据的刷新失败必须与成功状态同时可见。

### 7.2 管道页

- 桌面端横向显示 7 节点，小屏改为纵向；
- 节点展示状态、原因、最近成功/失败、本次行数、耗时、版本；
- 点击节点打开详情面板，展示完整已知字段、数据来源和更新时间；
- `detail_path` 只有目标页面已可用时才可点击；M4 Run 详情未完成前不生成死链接；
- 连接线只表达流程，不用绿色连线掩盖中间 `unknown`；
- apply 熔断场景必须同时显示映射失败和对象层使用旧结果；
- 部分服务不可达时其他可检测节点保持自身状态，不把整页替换为单个错误屏。

### 7.3 顶栏和状态管理

- `useOverviewStore` 唯一拥有 overview 请求、旧数据和刷新状态；
- `usePipelineStore` 唯一拥有 pipeline/services 请求及合并刷新状态；
- TopBar 只读取 store，显示环境、源状态、最近更新时间和隔离数；
- Dashboard/管道页不得直接调用 `fetch` 或另建 timer；
- store 使用现有 typed API service，不引入第二客户端；
- fixture 继续通过 `satisfies` 约束新响应结构。

## 12. 风险与降级边界

| 风险 | 处理方式 |
| --- | --- |
| 平台看不到中间机运行 | 显示 `unknown` 并说明跨机器证据缺失；不伪造 ERP/抽取健康 |
| raw/object 计数变慢 | 限制可信表范围、记录查询耗时；超预算返回 null + 告警，不缓存假值 |
| 服务探测拖慢轮询 | 每个探测有短超时、请求不重入、失败退避；保留上次成功时间 |
| legacy 时间无时区 | 边界集中转换并测试；解析失败为 unknown，M4 再做完整迁移 |
| 无 dataset version | 版本字段保持 null；仅用时间和 apply 状态表达旧结果 |
| ECharts 增大产物 | 按需 import、记录构建体积；不为简单对象分布引入第二图表实例 |
| M3 向 M4 膨胀 | 只加 run_type，不做运行详情/steps/数据浏览；详情入口按已实现能力启用 |
