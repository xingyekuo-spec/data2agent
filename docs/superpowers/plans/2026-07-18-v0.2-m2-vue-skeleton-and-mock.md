## 1. 目标

建立一个可以离线构建、可以在后端未启动时完整演示规定场景、并能安全切换到真实 API 的 Vue Console 工程骨架，为 M3–M6 页面开发提供统一的类型、状态、布局、Mock 和测试基础。

M2 完成后应满足：

- `console-ui/` 是独立的 Vue 3 + Vite + TypeScript 工程；
- OpenAPI 快照可以确定性生成 TypeScript 类型，前端不手写重复 API 类型；
- Mock 和真实模式经过同一 `openapi-fetch` 客户端与领域组件；
- 后端不启动时可切换并演示 10 个必备 Mock 场景；
- 8 个主页面和 Settings 路由均有稳定页面骨架；
- 页面能统一表达请求状态与领域健康状态，不把错误或未知显示为正常；
- 前端类型检查、单元/组件测试和生产构建进入 CI；
- 生产构建默认 `REAL`，不能因环境变量缺失而进入 Mock。

M2 验收的是**工程、契约、状态和演示骨架**，不是 M3–M6 业务页面的功能验收。

## 4. 核心实施决策

### 4.1 先补契约桩，不伪造后端完成度

M2 fixture 需要类型，但部分 v0.2 API 尚未实现。处理方式统一为：

1. 在后端定义 Pydantic request/response model；
2. 将目标路由加入 OpenAPI；
3. 未实现路由真实调用返回 `501 HttpError`；
4. 重新生成 `console-ui/openapi.json` 和 TypeScript 类型；
5. Mock 可以按已声明的 `200` schema 返回 typed fixture；
6. 页面在 DEMO/REAL 收到 `501` 时显示“尚未接入”，不能显示为空数据或健康。

M2 只补前端开发必需的契约，不实现查询、聚合、分页、鉴权或发布业务。

目标契约至少覆盖：

```text
GET  /api/pipeline
GET  /api/runs/{run_id}
GET  /api/data/raw/{source}/{table}
GET  /api/objects
GET  /api/objects/{object}
GET  /api/templates
POST /api/gateway/proposals
```

现有 `/api/overview`、`/api/services`、`/api/runs`、`/api/audit`、`/api/quarantine` 和 `/api/config` 直接复用。分页标准化和真实实现留在相应业务里程碑。

### 4.2 Mock 使用 MSW，客户端只有一套

不得为 Mock 编写第二套 store 或直接把 fixture 导入页面。统一数据流：

```text
页面 → Pinia store → typed API service → openapi-fetch → fetch
                                                  ├─ MOCK: MSW handler
                                                  └─ DEMO/REAL: 真实 /api
```

这样可以确保路径、请求体、错误处理和响应解析在三种模式下保持一致。

### 4.3 模式来自构建/部署配置，不来自 URL

使用单一配置 `VITE_CONSOLE_MODE=mock|demo|real`：

- 开发环境未设置时默认 `mock`；
- 生产构建未设置时强制默认 `real`；
- `demo` 调用真实展厅 API，不使用 fixture；
- URL query/hash 不能改变模式；
- Mock 场景可在仅 Mock 模式可见的开发面板中切换，但不能改变环境模式；
- 顶栏始终显示大写 `MOCK / DEMO / REAL`。

构建测试必须证明普通 `npm run build` 不会产出默认 Mock 应用。

### 4.4 请求状态与领域状态分离

请求生命周期：

```text
idle | loading | success | error
```

领域健康状态：

```text
unknown | idle | running | healthy | warning | failed | stale
```

网络失败属于请求 `error`，不能转换成 `success + []`；数据为空属于成功响应后的 `empty` 视图；后端无法检测属于领域 `unknown`。组件不得用一个布尔值混合三类含义。

### 4.5 API 类型是生成物

- `console-ui/openapi.json` 由 Python 脚本生成；
- `console-ui/src/types/api.ts` 由 `openapi-typescript` 生成并提交；
- 生成文件禁止手工修改；
- CI 先检查 OpenAPI，再重新生成 TypeScript 并检查 diff；
- 核心 API 与 fixture 不允许使用显式 `any`；动态 JSON 使用生成的递归 `JsonValue`。

### 4.6 Token 只保存在当前标签页

- 键名固定为 `d2a_token`；
- 仅使用 `sessionStorage`；
- `openapi-fetch` middleware 在请求时添加 `Authorization: Bearer`；
- `401` 清除无效 Token 并进入认证提示状态；
- Token 不进入 Pinia 持久化、URL、console、错误正文或 fixture；
- 不引入 axios 或第二套拦截器。

## 6. 必备 Mock 场景矩阵

所有 fixture 必须使用 `satisfies` 对生成类型进行编译期校验；禁止 `as any`。

| ID | 场景 | 关键响应/状态 | 页面必须表达 |
| --- | --- | --- | --- |
| `healthy` | 全链路正常 | 服务可达、最近运行成功、无隔离 | `healthy`，显示来源与更新时间 |
| `empty-install` | 首次安装、没有数据 | setup/空集合/从未运行 | 空状态或 `unknown`，不能显示 0 即健康 |
| `sync-running` | 同步运行中 | Run 为 running，带开始时间/步骤 | `running` 和进行中提示 |
| `ingest-failed` | 推送失败 | 管道推送节点 failed，带错误摘要 | 明确失败节点，其他节点不被连带变绿 |
| `apply-circuit-broken` | apply 熔断并使用旧版本 | 映射失败、对象层 stale、稳定版本仍服务 | `failed + stale` 双重语义 |
| `partial-services-down` | 部分服务不可达 | console 正常，MCP 或 ingest 失败 | 局部 failed，不把整页转为空 |
| `quarantine-pending` | 存在未处理隔离 | 隔离数量、对象和原因 | warning 与待处理数量 |
| `draft-governance` | binding/指标仍为 draft | 治理状态 draft | warning，明确“未经现场校准” |
| `token-invalid` | Token 无效 | API 返回 401 HttpError | 认证提示，不能显示空业务数据 |
| `unknown-error` | API 返回未知错误 | 500/非预期响应或网络异常 | error/unknown，显示可重试和诊断摘要 |

每个场景至少有一个组件或 store 测试；`healthy` 不得成为 fixture 解析失败时的 fallback。

## 7. package scripts 与构建约定

`package.json` 至少提供：

```text
npm run dev              # 开发服务;默认 Mock
npm run dev:real         # 连接本机 :8849
npm run api:generate     # openapi.json → src/types/api.ts
npm run api:check        # 重新生成并检查 git diff
npm run lint
npm run typecheck
npm run test
npm run build            # 生产构建;默认 REAL;base=/v1/
npm run preview
```

约束：

- Node 22，npm 和 `package-lock.json` 作为唯一包管理基线；
- CI 使用 `npm ci`，不使用 `npm install`；
- 不同时提交 npm/pnpm/yarn 多种锁文件；
- `dist/`、coverage 和 Node cache 不提交；
- 所有运行时依赖必须打包，HTML 不引用 CDN；
- ECharts 可以作为依赖安装，但 M2 不实现业务图表。
