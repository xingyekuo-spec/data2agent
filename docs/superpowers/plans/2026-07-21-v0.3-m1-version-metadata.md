## 1. 目标

为 v0.3 后续的原子发布、字段血缘和 MCP evidence 建立共同版本身份：系统能够确定“使用了哪一版模板、哪一份 binding、构建了哪一个对象版本、它属于哪一个数据集版本”，并能在旧 SQLite 落地库上幂等升级。

M1 只建立身份、持久化和只读契约，不改变当前 `obj_*` 发布方式。影子构建、原子切换、发布和回滚行为在 M2 完成。

## 2. 固定契约

### 2.1 版本标识

| 标识 | 规则 | M1 责任 |
| --- | --- | --- |
| `template_version` | `pack.yaml.version` 原样字符串 | 明确读取来源并持久化 |
| `binding_hash` | `sha256:` + 规范化 binding 语义内容的 64 位十六进制摘要 | 提供确定性计算与变化测试 |
| `object_version` | 数据集内单个对象构建版本 | 建立非空持久化字段；M2 产生 |
| `dataset_version` | 一组兼容对象版本的统一发布标识 | 建立主记录；M2 产生与发布 |

### 2.2 binding 规范化

摘要包含影响运行语义的 `source/tables/status/key_map/field_map/derived/watermark`：

- map 的键按字典序规范化；
- derived 规则列表保留顺序，因为“首个匹配生效”；
- Unicode 使用 UTF-8 原文，不依赖 YAML 排版；
- `notes` 是人读说明，不进入摘要；
- 摘要算法带 `sha256:` 前缀，避免未来算法含混。

### 2.3 元数据状态

数据集状态固定为 `building / published / failed / retired`；对象构建状态固定为 `building / built / failed / published / retired`。M1 在存储层建立约束，M2 才实现状态迁移和原子发布。

## 3. 存储结构

`d2a_dataset_version` 至少记录：

```text
dataset_version / source / template_version / status
built_at / published_at / previous_dataset_version / error / object_manifest
```

`d2a_object_version` 至少记录：

```text
dataset_version / object / object_version / binding_hash
row_count / batch_id / build_table / status / built_at / published_at
```

约束：一个数据集内每个对象只有一个对象版本；一个 source 同时最多只有一个 `published` 数据集；`object_manifest` 冻结数据集的对象成员集合，完整性判断不依赖当前模板；旧库初始化和重复初始化均不得丢失现有表或数据。

## 4. 任务顺序

| ID | 任务 | 自身门禁 |
| --- | --- | --- |
| M1-T01 | 实现 binding 规范化和摘要 | 排版/字典顺序/notes 变化摘要不变；运行语义变化摘要改变 |
| M1-T02 | 增加 dataset/object version DDL 和索引 | 新库结构正确；旧库幂等升级；单 source published 唯一 |
| M1-T03 | 增加类型化只读查询模型 | 空库、building、published、历史版本查询语义明确 |
| M1-T04 | 冻结 datasets 管理 API/OpenAPI 契约 | 列表/详情可只读；publish/rollback 在 M2 前 fail-closed |
| M1-T05 | 前端生成类型和“尚未发布”兼容 | OpenAPI/TS 无漂移；v0.2 页面不把空版本显示为健康 |
| M1-T06 | 全量回归与证据归档 | M1 退出门禁全部通过 |

## 5. 测试矩阵

- 同一 binding 的 YAML/字典键顺序变化不改变摘要；
- `notes` 变化不改变摘要；
- tables、status、key/field map、derived 规则顺序或 watermark 变化改变摘要；
- 新建落地库自动具备两张版本表和必要索引；
- 对既有 v0.2 落地库重复初始化不报错、不修改业务数据；
- 非法状态、重复对象版本和同 source 双 published 被数据库拒绝；
- 冻结对象清单缺失、损坏、成员缺失、出现额外成员或任一成员未发布时均 fail-closed；
- 当前模板升级或来源无绑定时，已发布数据集仍按自身冻结清单判断完整性；
- 空元数据保持“尚未启用/尚未发布”，不伪造版本；
- 现有 apply、MCP、Console 和模板加载测试无回归。
