## 1. 目标

把 M3 的聚合观测推进为可追溯、可核对的只读工作台，使用户不访问 SQLite、不执行任意 SQL、不解析自由文本日志，也能完成以下工作：

1. 查看 sync、apply、reconcile、ingest 的运行列表和结构化详情；
2. 解释一次运行处理了哪些表、对象或批次，行数、隔离数和水位发生了什么变化；
3. 按来源、动作和时间浏览 SQL 审计；
4. 在服务端白名单、分页和数量上限内浏览 raw 与对象层数据；
5. 按后端声明的业务键搜索，查看与表格同源的安全 JSON 响应；
6. 区分敏感、已脱敏、未知分类和被截断字段；
7. 追踪谁在何时访问了哪一类 raw 数据，而不把 Token 或原始敏感值写入审计；
8. 明确历史运行缺少 step 证据，而不是把它伪装成“没有处理任何内容”。

M4 完成后，M2 中的运行、审计和数据占位页进入 Real 可验收状态；`GET /api/runs/{run_id}`、raw/object 浏览契约桩不再返回 501。M3 的 Dashboard、管道、Jinja2 管理页和 `/v0` 保持兼容。

## 4. 核心实施决策

### 4.1 Run 是统一外部模型，step 是可用性明确的事实

统一 Run 类型：

```text
sync | apply | reconcile | ingest
```

统一状态：

```text
running | ok | paused | failed | aborted
```

`validation` 在 v0.3 进入同一模型，M4 不另建第二套验收记录。历史 `run_type IS NULL` 保持未知，不强制回填为 sync。

新增 `d2a_run_step`，新运行按真实执行粒度写 step：

- sync：每个表一个 step；
- apply：每个对象一个 step；
- reconcile：每个表/segment 一个 step；
- ingest：每个 HTTP batch 一个 step，并以 batch/correlation 信息关联重试。

详情响应必须包含 `steps_state`：

```text
available | legacy_unavailable
```

旧运行没有 step 证据时返回 `legacy_unavailable`，不能返回一个会被解释成“实际处理 0 项”的正常空数组。新运行若确实没有进入工作单元，才允许 `steps_state=available` 且 `steps=[]`。

### 4.2 列表 wire shape 保持兼容

`GET /api/runs` 和 `GET /api/audit` 已有数组响应与旧消费方，M4 不改成分页 envelope：

- 响应正文继续是数组；
- `X-Total-Count` 返回当前筛选条件下的总数；
- 增加 `limit/offset` 和筛选参数；
- Vue service 将“数组 + 响应头”适配成内部 `Page<T>`；
- `limit` 默认 50、硬上限 100；`offset >= 0`；越界参数返回 422；
- OpenAPI 显式声明 `X-Total-Count`，不能让类型层看不到总数。

Run 的规范查询参数是 `type`，与控制台设计和领域字段一致；数据库列 `run_type` 只是内部实现。不得让前端同时维护 `type/run_type` 两套参数。

### 4.3 新浏览接口可以使用具名分页 envelope

raw/object 当前只有 501 桩，但 M2 已冻结 `rows/offset/limit/total` 字段并由 typed fixture 使用。M4 保留这些字段，只做加法扩展：

```text
rows / offset / limit / total / columns / sort / query / warnings / truncations
```

新增两个 M4 需要的辅助路由：

```text
GET /api/data/raw                 # 可浏览 raw 目录
GET /api/audit/access             # 控制台数据访问审计
```

它们是路线图 §8.1 API 方向的加法，不替换既有 `/api/data/raw/{source}/{table}` 和 `/api/audit`。前者解决前端不能猜物理表名的问题；后者避免把控制台访问事件伪装成 SQL 执行记录。

### 4.4 白名单先于动态 SQL

数据浏览统一进入 `data2agent/console/data_browser.py`，路由不得自行拼接表名或列名：

1. source 必须精确存在于已加载配置；
2. raw table 必须精确存在于后端目录，响应和 URL 使用逻辑名，物理表名不作为用户输入；
3. object 必须存在于模板元模型且已有合法物化表；
4. 允许展示、搜索、排序的列由目录/元模型生成；
5. 值始终使用参数绑定；标识符只来自已验证目录并由统一函数引用；
6. 不接受 SQL、表达式、客户端列清单、任意 `ORDER BY` 或跨表 join；
7. 不存在或不允许的资源返回 404，不用空数组掩盖；非法参数返回 422。

默认按声明主键稳定排序；框架创建且无声明主键的 SQLite 表才允许使用稳定 `rowid` 兜底，并在响应中说明排序来源。不能使用无排序的 `LIMIT/OFFSET`。

### 4.5 搜索只覆盖声明的业务键

查询参数 `q` 只搜索后端声明的业务键或主键：

- object：模板主键/业务键；
- raw：配置映射能确定的源主键；
- 无可用业务键时服务端返回 `searchable=false`，前端禁用搜索；
- 查询值参数化，长度有上限；
- 不提供全字段模糊搜索，不扫描 BLOB，不接受客户端指定搜索列。

### 4.6 脱敏、分类与 JSON 视图共用同一响应

列元数据至少包含：

```text
name / data_type / role / classification / masked / searchable
```

其中：

```text
role: business_key | data | metadata
classification: normal | sensitive | unknown
```

- 对象层依据模板 `sensitive` 永久服务端脱敏为 `***`；
- raw 中能由 binding/模板确认的敏感列同样服务端脱敏；
- 无法分类的 raw 列标为 `unknown` 并展示警告，不能默认为安全；
- v0.2 不提供 unmask 参数、角色或隐藏入口；
- 页面“原始 JSON”展示与表格同一个已脱敏、已截断响应，不再次请求原值；
- Token、认证头、完整 SQL 和原始敏感行不得出现在错误、日志或访问审计中。

### 4.7 raw 浏览需要显式管理主体

Real 模式 raw 浏览比普通只读页面使用更严格的门禁：

- 必须配置控制台 Token，且请求携带有效 Bearer Token；
- 未配置 Token 或认证失败均不返回 raw 数据；前者返回明确 403，后者沿用统一认证错误；
- 单 Token 模式的主体记为稳定标识 `console-admin`，不得记录 Token、前缀、哈希或指纹；
- 对象层已经服务端脱敏，可沿用控制台普通鉴权；
- Mock 数据保持 MOCK 标识，不放宽 Real 的安全门禁。

每次 raw 浏览尝试都写访问审计，包括允许和拒绝。这个 GET 的审计写入是强制安全副作用，不是业务数据写操作；除此之外，Runs/Audit/Data 页面加载不得触发业务写入。

### 4.8 SQL 审计与访问审计分开表达

- `/api/audit`：既有 `d2a_audit_log`，表示来源 SQL/ingest 等数据操作事实；
- `/api/audit/access`：新增 `d2a_console_access_audit`，表示控制台数据浏览事实；
- 两者在 Audit 页面分 tab 展示，共用分页交互但不混合字段含义；
- SQL 默认折叠、安全转义，不用 SQL 文本推断 Run 状态；
- raw 访问审计只记录主体、目标、允许/拒绝、原因码、查询形状、返回行数和时间，不记录 `q` 原文、返回值或认证材料。

### 4.9 响应预算与不可序列化值必须显式处理

- page `limit` 默认 50、上限 100；
- 单个字符串/二进制字段采用统一最大序列化预算，初始建议 64 KiB，最终值在 M4-T01 固定；
- 超限值返回安全预览并在行级 `truncated_fields` 中列明，不能静默裁剪；
- BLOB 返回具名二进制描述或受限 base64 预览，不把 Python bytes 直接交给 JSON encoder；
- 非有限数字、日期时间和其他 SQLite 值走统一 JSON-safe 转换；
- 页面清楚标记“已截断”，不能把预览当作完整值导出。

## 5. API 与领域契约

M4-T01 先在 `contracts.py` 固定下面语义，再实现存储、路由和页面。示意字段允许按现有命名风格微调，但不得改变本节的可用性、安全和兼容语义。

### 5.1 `GET /api/runs`

```text
query:
  limit=50       # 1..100
  offset=0       # >= 0
  type?          # sync | apply | reconcile | ingest
  status?        # running | ok | paused | failed | aborted

response body: RunSummary[]
response header: X-Total-Count

RunSummary
├─ id
├─ type: RunType | null
├─ status: RunStatus
├─ source: string
├─ started_at / finished_at: datetime | null
├─ duration_ms: integer | null
├─ tables / rows / quarantined: integer | null
├─ dataset_version: null                  # v0.3 前固定 null
├─ detail: string | null                  # 保留既有字段，安全截断，逐步弃用
├─ error: string | null
└─ error_id: string | null
```

排序固定为 `started_at DESC, id DESC`。legacy 时间解析失败时字段为 null，并保留可解释错误/未知提示，不能使用当前时间代替。

### 5.2 `GET /api/runs/{run_id}`

```text
RunDetailResponse
├─ RunSummary 全部字段
├─ steps_state: available | legacy_unavailable
└─ steps[]
   ├─ id / ordinal
   ├─ kind: table | object | segment | batch
   ├─ name                              # 保留 M2 字段；表示表/对象/segment/batch
   ├─ status: RunStatus
   ├─ started_at / finished_at / duration_ms
   ├─ batch_id: string | null
   ├─ rows_in / rows_out / quarantined / repaired / soft_deleted
   ├─ watermark_before / watermark_after: JsonValue | null
   ├─ error: string | null
   └─ error_id: string | null
```

- 不存在返回 404；
- step 按 `ordinal, id` 稳定排序；
- 只返回安全错误摘要，不返回 traceback、Token 或完整原始行；
- M3 管道 `detail_path` 在有对应 run 时可指向 `/runs?run_id=<id>`。

### 5.3 `GET /api/audit`

```text
query:
  limit / offset
  source?
  action?
  from? / to?        # 带时区 ISO 8601；闭开区间 [from, to)

response body: AuditRecord[]
response header: X-Total-Count
```

`AuditRecord` 保留既有 `ts/source/action/sql/rows/duration_ms`，加法增加稳定 `id`，并把可解析时间规范化为带时区字符串。筛选必须参数化；`from >= to` 返回 422。排序固定为 `ts DESC, id DESC`。SQL 字段可以展示已记录文本，但必须由 Vue 文本节点安全渲染、默认折叠，并有服务端响应长度预算。

### 5.4 `GET /api/audit/access`

```text
query:
  limit / offset
  subject?
  resource_type?     # raw | object
  allowed?           # true | false
  from? / to?

AccessAuditPage
├─ items[]
│  ├─ id / ts / subject
│  ├─ resource_type / source / resource
│  ├─ allowed / reason_code
│  ├─ offset / limit / returned_rows
│  └─ request_id: string | null
├─ offset / limit / total
└─ generated_at
```

M4 raw 访问必须写；object 访问可同批接入，若未接入必须在契约和页面明确“当前仅审计 raw”。

### 5.5 `GET /api/data/raw`

```text
RawTableCatalogResponse
├─ items[]
│  ├─ source
│  ├─ table                    # 逻辑表名
│  ├─ display_name
│  ├─ rows: integer | null
│  ├─ latest_batch_id: string | null
│  ├─ extracted_at: datetime | null
│  ├─ searchable
│  └─ classification_warning
└─ generated_at
```

目录只包含当前配置允许且确实存在的表。计数失败使用 null 和警告，不伪装为 0；不得暴露任意 SQLite 内部表。

### 5.6 `GET /api/data/raw/{source}/{table}`

```text
query:
  limit / offset / q?

RawDataPageResponse
├─ source / table
├─ columns[]
├─ rows[]                              # 保留 M2 字段；每项仍是键值对象
├─ truncations[]
│  ├─ row_index
│  └─ fields[]
├─ offset / limit / total
├─ sort
├─ query
├─ searchable
├─ warnings[]
└─ generated_at
```

该接口执行 §4.7 的强鉴权和访问审计。逻辑删除行默认不展示；若未来需要展示必须新增显式契约，不能用隐藏查询参数。

### 5.7 `GET /api/objects`

```text
ObjectSummary[]
├─ object / display_name / domain
├─ rows: integer | null
├─ mapped_at: datetime | null
├─ quarantined: integer
├─ version: null                         # v0.3 前固定 null
├─ searchable
└─ warning: string | null
```

目录来自模板元模型与合法物化表的交集；未物化模板可返回 `rows=null` 和明确 warning，以支持用户解释缺失，不能把它伪装为有 0 行数据的正常对象。

### 5.8 `GET /api/objects/{object}`

与 raw page 采用同一分页、列元数据、截断和 `q` 语义，但对象敏感字段始终脱敏。不存在的对象返回 404，模板存在但尚未物化返回具名 409 或空态错误；M4-T01 固定其中一种，前端不得把它变成通用网络失败。

## 6. 存储、迁移与写入边界

### 6.1 `d2a_run_step`

建议最小字段：

```text
id INTEGER PRIMARY KEY
run_id INTEGER NOT NULL
ordinal INTEGER NOT NULL
kind TEXT NOT NULL
target TEXT NOT NULL
status TEXT NOT NULL
started_at TEXT NULL
finished_at TEXT NULL
batch_id TEXT NULL
rows_in / rows_out / quarantined / repaired / soft_deleted INTEGER NULL
watermark_before / watermark_after TEXT NULL       # JSON
error TEXT NULL
error_id TEXT NULL
```

索引至少覆盖 `(run_id, ordinal, id)` 和需要的 batch/correlation 查询。SQLite 兼容迁移使用 `CREATE TABLE IF NOT EXISTS`、`CREATE INDEX IF NOT EXISTS`，并测试新库、旧库和重复初始化。

step 写入跟随对应运行生命周期：开始时写 `running`，结束时更新最终状态和度量；异常路径必须尽力关闭 step 和 Run。进程硬崩溃留下的 running 仍按 M3 的孤儿规则诚实处理，不在读取时擅自改成 failed。

### 6.2 ingest Run 与幂等相关性

每个接收成功或进入处理的 ingest batch 建立 `type=ingest` 的 Run 和 batch step。使用稳定 correlation/batch 信息识别同一重试，避免同一个批次因 HTTP 重试产生多个互相矛盾的成功 Run。

M4-T03 必须先写重试、部分失败和异常回滚测试，再确定唯一索引或事务边界。不得因为 Run 观测写入失败而静默报告业务 ingest 成功；错误语义要明确区分“业务数据未写入”和“数据已写入但观测记录失败”。

### 6.3 `d2a_console_access_audit`

建议最小字段：

```text
id INTEGER PRIMARY KEY
ts TEXT NOT NULL
subject TEXT NOT NULL
resource_type TEXT NOT NULL
source TEXT NULL
resource TEXT NOT NULL
allowed INTEGER NOT NULL
reason_code TEXT NOT NULL
offset / limit / returned_rows INTEGER NULL
request_id TEXT NULL
```

严禁增加 Token、Token 指纹、查询值原文、返回数据、完整 SQL 或异常 traceback 列。索引覆盖 `ts`、`resource_type`、`allowed` 和常用筛选组合。

拒绝审计必须在不泄露资源存在性的前提下写入。若审计存储本身失败，raw 请求默认失败关闭，不在无审计证据时放行敏感浏览。

### 6.4 只读业务边界

M4 页面与浏览接口不得修改 raw、object、quarantine、template、binding、watermark 或业务运行状态。唯一允许的页面加载写入是 §6.3 的安全访问审计。测试必须对业务表做前后快照，证明浏览无业务副作用。

## 7. 前端交付设计

### 7.1 共用数据访问规则

- 新增 `useRunStore`、`useAuditStore`、`useDataStore`；
- route query 保存筛选、页码、tab、资源和 `run_id`，刷新后可恢复；
- store 使用请求代际或取消机制，后返回的旧请求不能覆盖新筛选结果；
- Run/审计/数据浏览不加入 M3 的全局 5 秒轮询；默认显式刷新；
- 所有页面复用 loading/empty/error/unknown 状态，保留上次成功数据时标记刷新失败；
- 每页一个请求所有者，不在表格行、卡片或详情组件内建立 timer；
- JSON 视图只 stringify 当前安全响应，不发起绕过脱敏的新请求。

### 7.2 运行页

- Run type、status 筛选，服务端分页和总数；
- 列表显示类型、来源、状态、开始/结束、耗时、表/行/隔离数；
- `run_id` route query 自动打开详情抽屉；
- 详情显示 Run 摘要、step 表、水位 before/after、批次、错误和原始安全 JSON；
- `legacy_unavailable` 显示“历史记录没有逐步证据”，不能显示“0 个步骤”；
- M3 Dashboard/管道可链接到运行详情，无效 ID 显示可恢复 404；
- 不出现 sync/apply/reconcile/retry 按钮。

### 7.3 审计页

- “SQL 操作”与“数据访问”两个 tab；
- SQL 操作支持 source、action、时间范围和分页；
- 数据访问支持资源类型、允许/拒绝、主体、时间范围和分页；
- SQL 与错误文本默认折叠、转义、按预算截断；
- 无自动轮询，筛选变化取消/淘汰旧请求；
- 访问审计未覆盖对象浏览时显示准确范围说明。

### 7.4 数据页

- Raw/Object 两个 tab；
- Raw 先加载目录，选择 source/table 后加载页面；Object 先加载对象目录；
- 表格由服务端 columns 驱动，但只渲染安全类型，不使用动态 HTML；
- 业务键搜索、上一页/下一页、每页数量和显式刷新；
- 显示批次、抽取/映射时间、分类、脱敏和截断标记；
- `unknown` 分类显示持续警告，敏感字段显示脱敏标识；
- JSON 面板展示当前 page 响应，可复制已脱敏 JSON，不提供原值复制；
- raw 因未配置 Token 被 403 时显示安全配置指引，不降级到对象数据或 Mock。

## 9. 测试设计

### 9.1 后端必测矩阵

- migration：全新库、M3 旧库、重复初始化、部分索引已存在；
- Run：四种类型、五种状态、正常/失败/paused/aborted、legacy null type、legacy 无 step；
- step：顺序、表/对象/segment/batch 度量、水位 JSON、错误截断、孤儿 running；
- ingest：重复 batch/correlation、部分失败、观测写入失败、事务边界；
- runs/audit：limit/offset、type/status/source/action/time、总数、空页、422、稳定排序；
- browse：合法目录、未知 source/table/object、逻辑删除、无主键兜底、页间不重复；
- search：业务键、无业务键、超长 q、SQL 注入、通配/转义边界；
- security：未配置 Token、错误 Token、有效 Token、对象脱敏、raw 已知敏感脱敏、未知分类；
- access audit：允许、拒绝、审计写入失败、主体/目标/行数正确、无 Token/q/返回值；
- serialization：null、datetime、非有限数字、bytes/BLOB、Unicode、64 KiB 边界、截断字段；
- compatibility：既有 `/api/runs`、`/api/audit` 数组 shape，Jinja2、`/v0` 和 action API 不回归；
- side effects：浏览前后 raw/object/quarantine/watermark 不变，只有访问审计增加。

### 9.2 前端必测矩阵

- store：筛选/分页、响应头总数、请求代际、失败保留旧数据、route query 恢复；
- Runs：空、loading、error、unknown type、五种状态、legacy_unavailable、step 失败、404 深链；
- Audit：双 tab、时间范围、折叠 SQL、无 HTML 执行、访问审计空态；
- Data：目录空、未物化对象、分页、搜索、未知分类、脱敏、截断、BLOB、JSON 同源；
- Auth：raw 403 引导、401 清理 Token、认证恢复后显式重试；
- Mock：healthy/empty/running/failure/unreachable/token-invalid/unknown-error 等既有场景继续可演示；
- production：构建产物无 MSW、fixture、Token、原始敏感样例。

### 9.3 浏览器验收

至少覆盖：

1. Mock 中从运行列表打开 step 详情，再通过 URL 恢复同一 run；
2. Real 临时 SQLite 中执行一次 sync/apply/reconcile/ingest 后能看到对应结构化 step；
3. legacy Run 显示“逐步证据不可用”；
4. SQL 审计按 source/action/time 筛选，分页总数正确；
5. raw 无 Token 被拒绝且产生不泄密的拒绝审计；
6. raw 有效 Token 可浏览白名单表，敏感/未知/截断标识正确；
7. object 敏感字段在表格和 JSON 中都不可见；
8. 注入式 source/table/q 不执行且返回 404/422；
9. 数据浏览不改变业务表、水位和隔离状态；
10. Dashboard/管道到 Run 详情的链接可用，旧 Jinja2 和 `/v0` 仍可访问。

## 11. 退出门禁

M4 只有同时满足以下条件才能从“进行中/待验收”改为“已完成”：

- [ ] sync、apply、reconcile、ingest 新运行都进入统一 Run + step 模型；
- [ ] legacy 运行缺少 step 时明确显示不可用，没有伪造或猜测回填；
- [ ] 用户能解释目标、行数、隔离数、批次和水位变化，不解析日志或 SQL 判断状态；
- [ ] Runs 列表筛选/分页/总数和详情深链可用，既有数组 wire shape 兼容；
- [ ] SQL 审计支持 source、action、时间和服务端分页；
- [ ] raw/object 只允许白名单资源、服务端分页、稳定排序和声明业务键搜索；
- [ ] `limit` 有默认值和硬上限；BLOB/超大值可安全序列化并显式标记截断；
- [ ] 对象和 raw 已知敏感字段服务端脱敏，未知 raw 分类持续可见；
- [ ] raw Real 浏览必须有有效管理 Token，每次允许/拒绝都有不泄密访问审计；
- [ ] 表格与 JSON 视图同源，JSON 不绕过脱敏和截断；
- [ ] 页面加载除访问审计外不产生业务写入，不出现 Vue 动作按钮；
- [ ] Mock/Real 浏览器验收通过，M3 Dashboard/管道链接和旧 Jinja2/`v0` 未回归；
- [ ] OpenAPI、TypeScript、fixture、CI 和分发产物一致；
- [ ] §10 全量命令通过，证据与最终提交号回填到本文件及执行索引。

## 12. 主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 为旧运行补造 step 导致错误追溯 | `legacy_unavailable`，不猜测回填 |
| 数组改 envelope 破坏旧页面 | 正文保持数组，总数使用声明响应头 |
| 动态表名形成 SQL 注入 | 配置/模板目录精确成员校验 + 统一标识符引用 |
| `OFFSET` 无稳定排序造成重复/漏行 | 主键排序；仅框架 SQLite 表允许 rowid 兜底 |
| raw 暴露个人或业务敏感值 | 强 Token、服务端脱敏、未知分类警告、访问审计、失败关闭 |
| “原始 JSON”绕过表格保护 | JSON 只展示同一个安全 page 响应 |
| 审计本身记录秘密 | 固定字段白名单，不记录 Token/q 原文/返回值/traceback |
| 大字段/BLOB 使响应或页面失控 | limit、单值预算、JSON-safe 转换、显式截断 |
| ingest 重试产生重复 Run | batch/correlation 幂等测试后固定事务/唯一性 |
| 三页同时实现压垮 1–2 人 | 先后端共享内核，再逐页交付，按任务门禁不按周赶工 |
| M4 顺带开放写操作 | Vue 无动作按钮，写 API 不属于本里程碑验收 |

## 13. 交付 M5 的稳定输入

M4 关闭时应向 M5 提供：

- 可复用的 Run + step 详情和安全错误表达；
- 统一分页、稳定排序、字段分类、脱敏、截断与 JSON-safe 浏览组件；
- 可复用的审计 tab、筛选和访问审计基础；
- 已验证的对象目录，可供模板只读页关联物化状态；
- 可从 Run/step 关联 quarantine 失败的具名 ID/目标，但不提前实现隔离处理；
- 完整 Mock/Real 鉴权与 403/404/409/422 状态表达；
- 最终门禁数字、实现提交号、复审修复和仍留给 M5/M6/v0.3 的明确事项。

M4 不以“页面看起来有数据”为完成标准；只有当数据来源、权限、分页、脱敏、审计和历史证据缺口都能被自动验证并被页面诚实表达时，才能进入 M5。
